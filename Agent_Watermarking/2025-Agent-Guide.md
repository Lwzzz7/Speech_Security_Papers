# Agent Guide：面向智能体高层行为的概率偏置水印

> 论文：**Agent Guide: A Simple Agent Behavioral Watermarking Framework**  
> 作者：Kaibo Huang, Zipei Zhang, Zhongliang Yang, Linna Zhou  
> 版本：arXiv:2504.05871v3，首次提交于 2025 年 4 月 8 日，最新版本更新于 2026 年 5 月 31 日  
> 代码：Agent Guide 的实现已作为基线并入 [AgentMark](https://github.com/Tooooa/AgentMark) 仓库

## 0. 摘要翻译

随着智能体在社交媒体等数字生态中的部署不断增加，其可追踪性与问责问题日益突出，尤其是在网络安全和数字内容保护场景中。传统的大语言模型水印通常依赖 token 级操控，但智能体的行为难以直接 token 化，而且从高层行为决策转换为具体动作时会发生信息损失，因此这类方法并不适合直接用于智能体。

为解决上述问题，论文提出 **Agent Guide**，一种面向智能体的行为水印框架。其核心思想是把智能体决策解耦为两个层次：高层的 **行为**，例如选择收藏；以及低层的 **动作**，例如使用某个标签执行收藏。框架通过对行为概率分布施加由密钥控制的偏置来嵌入水印，同时让具体动作仍由语言模型自然生成，从而尽量保持执行结果的自然性。检测阶段统计多轮交互中实际行为命中密钥指定行为集合的次数，并利用 z 统计量判断水印是否存在。作者在社交媒体模拟场景和多种智能体画像上进行实验，报告了可分离的检测结果和较低误报率，并将该框架定位为恶意智能体识别与专有智能体版权保护的一种基础方案。

## 1. 方法动机

### 1.1 为什么普通文本水印不足以覆盖智能体

文本水印保护的是模型“说了什么”，而智能体安全往往还关心它“做了什么”。例如，一条由模型生成的欺诈帖子属于内容层问题；智能体持续转发、收藏或放大该帖子，则属于行为层问题。后者包含决策意图、交互频率和长期策略，仅查看最终文本并不能完整刻画。

将 token 水印直接迁移到智能体还存在两个错位：

1. **表示错位**：收藏、分享、浏览、调用工具等行为是离散决策，不等同于自然语言 token。
2. **接口错位**：许多智能体使用闭源 LLM API，部署者不能修改模型参数或直接访问 logits。
3. **转换损失**：高层决策被执行器转换成 API 调用或环境动作后，原始语言表达可能完全消失，文本水印也随之丢失。

因此，论文把水印承载位置从输出文本上移到 **规划层的行为选择分布**。只要智能体持续执行由该分布采样出的行为，检测者就能从一段轨迹中恢复统计信号。

### 1.2 核心直觉

Agent Guide 不强制每轮执行固定动作，而是使用密钥和轮次选出一组“绿色行为”，再适度提高这些行为的概率。单轮选择仍具随机性，多轮之后绿色行为的命中次数会系统性高于无水印假设。其设计逻辑与 LLM 绿色 token 水印相似，但载体从 token 替换为行为类别。

### 1.3 论文真正解决的问题

该方法解决的是 **行为轨迹的水印存在性检测**：给定密钥和按轮次记录的高层行为，判断轨迹是否由启用 Agent Guide 的智能体产生。它不是单轮身份认证，也没有在当前设计中编码多比特所有者 ID，更没有给出密码学不可伪造性证明。

## 2. 威胁模型解读

### 2.1 参与方与能力

- **水印所有者**：能够在智能体的规划决策与动作执行之间插入 Agent Guide 模块，持有密钥，并能定义行为集合。
- **被保护智能体**：使用 LLM 根据事件、角色画像和历史记忆输出行为概率，再由水印模块完成偏置与采样。
- **验证者**：拥有密钥、行为集合、轮次编号以及一段可观测的行为日志，能够重建每轮对应的引导集合。
- **普通观察者**：看到具体动作或平台交互，但不知道哪些行为由密钥选为引导对象。

### 2.2 检测目标

论文检验的是两个假设：无水印轨迹中，引导集合的命中次数符合基准分布；有水印轨迹中，命中次数因概率偏置而显著增加。检测输出只是“存在或不存在”，没有恢复载荷。

### 2.3 论文没有覆盖的攻击者

当前实验并未真正建立主动攻击模型。以下现实攻击均未评估：

- 删除部分日志、截断轨迹或只提交对攻击者有利的轮次；
- 插入、重排行为导致验证者与嵌入端的轮次不同步；
- 观察到大量轨迹后估计哪些行为经常被提升，再反向抑制这些行为；
- 使用另一层策略重采样、改写或替换原始行为；
- 获取密钥后伪造带水印轨迹，或使用错误密钥进行归属冲突攻击；
- 改变行为集合、合并行为标签或用近义动作绕过固定分类器。

因此，论文所称的“鲁棒性”主要指不同角色画像下仍能检测，而不是针对水印移除、伪造和同步破坏的对抗鲁棒性。

## 3. 方法设计与复现级理解

### 3.1 系统组成

框架包含五个模块：记忆模块、事件生成模块、行为概率生成模块、Agent Guide 水印模块和动作执行模块。预定义行为集合记为：

$$\mathcal{B}=\{b_1,b_2,\ldots,b_m\}$$

在第 `r` 轮，系统根据角色画像与反思记忆生成事件 `e_r`；LLM 再结合事件、记忆和行为列表生成归一化行为概率：

$$P_r=\{p_r(b_1),p_r(b_2),\ldots,p_r(b_m)\},\qquad \sum_{i=1}^{m}p_r(b_i)=1$$

Agent Guide 修改该分布并采样高层行为，动作执行模块则依据被选行为生成具体动作。最后，事件、行为和动作写回记忆，进入下一轮。

### 3.2 行为与动作的两层解耦

论文最重要的工程判断是：**只在行为层嵌入，不直接控制动作文本**。

- 行为层回答“这一轮做哪一类事情”，例如点赞、收藏、分享或浏览。
- 动作层回答“以什么对象、参数和语言形式执行”，例如收藏某个旅游帖子并附带特定标签。

水印模块只决定行为类别，动作细节仍由 LLM 根据上下文生成。这样可以避免把固定短语、特殊参数或异常文本直接暴露在输出中。不过，“动作自然性不受影响”只是设计目标，论文没有用人工评价、语义指标或任务成功率验证这一点。

### 3.3 密钥如何产生引导集合

在每一轮中，密钥 `k` 和轮次 `r` 应当共同确定两个量：偏置强度 `gamma`、被引导行为数 `n`，以及一个大小为 `n` 的行为子集：

$$\mathcal{B}_{g,r}=Select(\mathcal{B},k,r,n),\qquad |\mathcal{B}_{g,r}|=n$$

为了防止水印过弱，作者设置两个下界：

$$\gamma_r=\max(\gamma_r,\gamma_{min}),\qquad n_r=\max(n_r,n_{min})$$

这里存在关键复现缺口：论文没有给出从 `k` 和 `r` 到随机种子、偏置强度、子集大小以及具体子集的完整映射，也未规定所使用的哈希函数或伪随机函数。仅知道密钥为 2025，不能独立重现每一轮的引导集合。

### 3.4 概率偏置与归一化

对属于引导集合的行为，概率乘以 `1+gamma`；其他行为保持不变：

$$\widetilde{p}_r(b_i)=p_r(b_i)(1+\gamma_r),\quad b_i\in\mathcal{B}_{g,r}$$

$$\widetilde{p}_r(b_i)=p_r(b_i),\quad b_i\notin\mathcal{B}_{g,r}$$

随后重新归一化：

$$p'_r(b_i)=\frac{\widetilde{p}_r(b_i)}{\sum_{j=1}^{m}\widetilde{p}_r(b_j)}$$

最后从新分布中随机采样行为：

$$b_r^*\sim P'_r$$

若原始分布落在引导集合上的总概率质量为 `q_r`，偏置后的总质量可直接写成：

$$q'_r=\frac{(1+\gamma_r)q_r}{1+\gamma_r q_r}$$

这个式子揭示了检测强度的来源：`gamma` 越大，引导集合的命中概率越高；但与此同时，行为分布被改变得越明显，任务效用与隐蔽性风险也越大。论文没有报告这一权衡曲线。

### 3.5 动作生成与记忆更新

采样得到行为后，执行模块将事件、反思记忆和选中行为重新交给 LLM，生成具体动作 `a_r`。记忆更新为：

$$\mathcal{M}_{r+1}=Update(\mathcal{M}_r,e_r,b_r^*,a_r)$$

这一设计让后续事件和决策依赖过去轨迹，因此各轮样本并不严格独立。检测端却使用独立同分布的二项近似，这一建模差异需要在更严格的统计检验中处理。

### 3.6 水印检测

验证者使用相同密钥和轮次重建每轮引导集合，并统计实际行为命中的总次数：

$$X=\sum_{r=1}^{N}\mathbf{1}[b_r^*\in\mathcal{B}_{g,r}]$$

论文把无水印条件下的命中概率设为引导集合占全部行为的比例：

$$p_0=\frac{|\mathcal{B}_{g}|}{|\mathcal{B}|}$$

于是采用二项分布近似：

$$X\sim Binomial(N,p_0)$$

无水印条件下的均值和标准差为：

$$\mu_0=Np_0,qquad \sigma_0=\sqrt{Np_0(1-p_0)}$$

最终统计量为：

$$z=\frac{X-\mu_0}{\sigma_0}$$

当 `z` 高于阈值 `tau` 时判定存在水印。实验使用六种行为、每轮至少引导三种行为，因此默认 `p_0=0.5`；在 50 轮设置下：

$$\mu_0=25,qquad \sigma_0=\sqrt{12.5}\approx3.536$$

由此可知，表中 `z=4.53` 大致对应 50 轮里有 41 次命中引导集合，而 `z=4.24` 对应约 40 次命中。

### 3.7 从输入到检测的完整流程

复现时可以按照下面的顺序实现：

1. 固定行为集合、密钥、角色画像和初始记忆。
2. 每轮由 LLM 根据画像和记忆生成事件。
3. 再提示 LLM 为所有候选行为返回结构化、可解析且和为 1 的概率。
4. 由密钥与轮次确定引导子集、子集大小和偏置强度。
5. 提升引导行为概率、归一化并随机采样高层行为。
6. 根据高层行为生成具体动作并更新反思记忆。
7. 保存轮次编号和行为标签，形成长度为 `N` 的轨迹。
8. 验证时重建每轮引导集合，统计命中次数并计算 z 分数。
9. 使用预先固定的阈值进行一次性存在性判定。

### 3.8 检验假设中的关键问题

论文直接使用 `n/m` 作为无水印命中概率，但原始行为分布通常不是均匀分布。更精确的逐轮无水印命中概率应为：

$$q_r=\sum_{b_i\in\mathcal{B}_{g,r}}p_r(b_i)$$

如果引导集合在每轮都由安全伪随机函数均匀选取，并且与事件和原始概率分布独立，那么从密钥随机性上平均后，期望可能接近 `n/m`。但对一个固定密钥、相关的多轮记忆和非均匀行为偏好，这个等式并不自动成立。更稳妥的零假设应基于逐轮 `q_r` 建模，或通过大量无水印轨迹经验校准阈值。

此外，论文把 `tau=2` 描述为显著性水平 0.05。对单侧标准正态检验，0.05 对应的常用阈值约为 1.645；阈值 2 对应约 0.0228 的单侧尾概率。它确实更保守，但论文的统计表述不够精确。

## 4. 与相关方法的区别

| 方法类别 | 水印载体 | 是否需要训练或模型权重 | 检测对象 | Agent Guide 的区别 |
|---|---|---:|---|---|
| LLM 绿色 token 水印 | 输出 token 分布 | 通常需要 logits 或采样接口 | 生成文本 | 将绿色集合从 token 空间迁移到行为集合 |
| 模型参数或后门水印 | 模型权重与触发响应 | 需要训练、微调或可访问参数 | 模型响应 | Agent Guide 可包裹闭源 API，不改模型参数 |
| 输出内容指纹 | 文本、图像或音频内容 | 依方法而定 | 单个内容样本 | Agent Guide 检测跨多轮决策规律，而非单个输出 |
| 网络隐蔽信道 | 数据包时间、流量或协议行为 | 需要网络层控制 | 通信流 | Agent Guide 操作的是语义化的高层智能体行为 |
| 后续 AgentMark | 行为轨迹与多比特编码 | 可作为智能体中间层 | 所有权与多比特归属 | AgentMark 进一步强调效用保持、分布保持和抗轨迹擦除；Agent Guide 是更简单的单比特基线 |

Agent Guide 的优点是接口简单：只要能在“规划概率输出”和“动作执行”之间插入采样器，就不需要访问底层 LLM 权重。但它与绿色 token 水印一样会改变原始分布，而且论文没有证明这种改变不可感知或不降低任务效用。

## 5. 实验设置与结果解读

### 5.1 实验配置

| 项目 | 论文设置 |
|---|---|
| 场景 | 社交媒体智能体模拟 |
| 行为集合 | 点赞、收藏、分享、评论、浏览、下载，共 6 种 |
| 交互长度 | 每条轨迹 50 轮 |
| 重复次数 | 每种角色画像重复 2 次 |
| 角色画像 | 活跃/不活跃 × 平静/愉悦/悲伤，共 6 种 |
| 密钥 | 2025 |
| 最小偏置强度 | 0.5 |
| 最小引导集合大小 | 3 |
| 检测阈值 | z 分数大于 2 |
| 主要指标 | z 分数与作者声称的误报率 |

### 5.2 主要结果

所有加水印轨迹的平均 z 分数都高于阈值 2：

| 画像 | 无水印平均 z | 加水印平均 z |
|---|---:|---:|
| Active + Calm | 0.71 | 4.53 |
| Active + Joyful | 0.57 | 4.38 |
| Active + Sad | 0.57 | 4.67 |
| Inactive + Calm | 0.99 | 4.24 |
| Inactive + Joyful | 0.85 | 4.24 |
| Inactive + Sad | 0.85 | 4.53 |

从这组数据看，当前模拟设置中水印与无水印轨迹完全分离。最低水印平均 z 为 4.24，最高无水印单次 z 为 1.41，和阈值 2 之间存在明显间隔。

### 5.3 结果能说明什么

- 行为概率偏置确实能在 50 轮轨迹上形成强统计信号。
- 活跃度和情绪画像没有破坏检测结果，说明在作者给定的六种 prompt 配置下，该信号较稳定。
- 检测不依赖动作的具体文本，只需得到规范化的行为标签和正确轮次。

### 5.4 结果不能说明什么

1. **不能证明真实误报率低于 5%**：每种画像只有两次无水印运行，总计样本量非常小；观察到零误报并不足以精确估计尾部概率。
2. **不能证明任务效用不变**：论文没有报告任务完成率、行为分布距离、用户偏好一致性或动作自然性评价。
3. **不能证明对攻击鲁棒**：没有日志丢失、轨迹截断、行为替换、轮次错位、密钥猜测或水印伪造实验。
4. **不能证明跨模型与跨环境泛化**：实验只有一个社交媒体模拟范式，没有 ToolBench、具身环境或真实平台评测。
5. **缺少公平基线**：没有与 token 水印、无偏置随机策略或其他行为指纹方案做量化比较。
6. **缺少消融**：没有系统改变轨迹长度、偏置强度、引导比例和行为集合规模，无法观察检测率、隐蔽性与效用之间的 Pareto 曲线。

### 5.5 一个值得复核的数值现象

若六种行为中有三种被引导、原始引导质量刚好为 0.5，并且只使用最小偏置 0.5，则偏置后命中概率为：

$$q'=\frac{1.5\times0.5}{1+0.5\times0.5}=0.6$$

在 50 轮下，对应的期望 z 分数约为：

$$E[z]=\frac{50\times0.6-25}{\sqrt{12.5}}\approx1.41$$

这低于论文报告的 4.24–4.67。说明实际运行中的偏置强度、引导子集大小或原始概率质量应明显高于这个简单下界，但论文没有报告每轮 `gamma`、`n` 和 `q_r` 的实际分布。这是复现实验时最需要补齐的信息。

## 6. 对后续研究的启发

### 6.1 从内容水印扩展到决策水印

这篇论文提供了一个重要视角：生成式系统的可追踪信号不必只存在于最终媒体或文本中，也可以存在于连续决策轨迹。对于工具调用 Agent、对话式操作系统和具身智能体，可以把 API 类别、规划节点、工具选择或运动原语定义为行为字典，再在不直接篡改动作参数的前提下嵌入统计信号。

### 6.2 更合理的后续方案

- 使用带密钥的密码学伪随机函数，根据环境上下文而非纯轮次生成引导集合，避免删除或插入一步后永久失步。
- 根据每轮原始概率计算 Poisson-binomial 零假设，而不是固定使用 `n/m`。
- 引入纠错码和多比特载荷，将“是否存在”扩展为所有者或实例 ID 解码。
- 使用分布保持采样，使水印边际分布尽量接近原始行为策略，降低效用变化和被统计识别的风险。
- 同时测量任务成功率、行为分布距离、检测 AUC、固定 FPR 下 TPR，以及不同轨迹长度的样本效率。
- 将日志删除、截断、重排、行为替换、上下文改写和密钥泄漏纳入正式攻击矩阵。

### 6.3 与语音安全项目的关系

Agent Guide 不属于语音水印，但其“多轮统计累积”思想可以迁移到语音智能体：不必在每段语音中强行写入完整载荷，而可以在多轮对话中的说话风格、工具选择、响应策略或合成器控制变量上分散编码。不过此类行为水印必须额外关注用户体验、策略偏差和伦理风险，不能仅以检测成功为目标。

## 7. 一句话总结

**Agent Guide 将 LLM 绿色列表水印的概率偏置思想从 token 层提升到智能体行为层，通过密钥控制的多轮行为选择偏差实现简单的水印存在性检测，但当前证据只覆盖小规模社交模拟，尚未验证效用保持、主动攻击鲁棒性和严格的误报控制。**

## 9. 复现难度与注意事项

### 9.1 难度判断

**概念复现：低；严格复现：中到高。**

行为偏置和 z 检测本身非常简单，但要精确得到论文表格结果，需要知道 LLM 型号、完整 prompt、采样参数、事件数据来源、随机种子，以及密钥到 `gamma`、`n` 和引导集合的映射。正文没有完整提供这些信息。

### 9.2 最小复现清单

- 固定六类行为及其规范化标签；
- 保存所有轮次的事件、原始概率、引导集合、偏置后概率和最终行为；
- 固定 LLM 版本、temperature、top-p、随机种子和结构化输出解析方式；
- 明确使用哪种哈希或伪随机函数从密钥派生每轮参数；
- 至少生成数千条无水印轨迹做经验阈值校准；
- 扫描不同 `N`、`gamma`、`n`，同时报告检测与效用；
- 分开验证无攻击检测、错误密钥、日志丢失、截断、插入、重排和行为替换攻击。

### 9.3 代码使用注意

当前公开实现位于 AgentMark 仓库中，并被作者明确描述为 Agent Guide 基线。由于 AgentMark 是后续、更完整的行为水印框架，仓库的默认算法、实验环境和 README 主要服务于 AgentMark。复现本论文时应确认调用的是 Agent Guide/Oasis 基线逻辑，而不是把后续的分布保持采样、纠错编码和多比特机制误当成原论文组成部分。

## 10. 300–500 字总结

Agent Guide 是一项面向智能体行为轨迹的简单水印工作。它观察到传统 LLM 水印主要作用于 token 或模型参数，难以覆盖智能体在环境中执行的高层决策，于是将决策拆分为“行为”和“动作”两层：LLM 首先根据事件、角色画像和反思记忆输出点赞、收藏、分享等行为的概率；水印模块利用密钥和轮次选择一组引导行为，提高其概率并重新采样；动作执行器再围绕选中行为生成自然的具体操作。验证者用相同密钥重建每轮引导集合，统计 50 轮中行为命中集合的次数，并通过 z 分数进行存在性检测。实验在六种社交媒体用户画像上得到明显分离：无水印平均 z 为 0.57–0.99，加水印平均 z 为 4.24–4.67，均位于阈值 2 的两侧。方法的优点是无需训练或访问 LLM 权重，适合包裹 API 型智能体；但证据仍较初步。论文只进行两次重复，没有任务效用、动作自然性、强基线、参数消融和主动攻击实验；密钥派生过程也未完整说明，固定 `n/m` 的零假设对非均匀且存在记忆相关性的行为分布未必严格成立。因此它更适合作为行为水印概念验证和后续 AgentMark 的基础基线，而不能直接视为已经具备真实部署安全性的完整方案。

## 11. 论文写作逻辑

论文采用一条清晰但较短的论证链：

1. 从恶意智能体识别和专有智能体版权保护引出可追踪需求。
2. 指出模型权重水印无法适配闭源 API，token 水印又与高层行为不对齐。
3. 提出行为/动作二层抽象，将水印放在行为概率而非动作文本中。
4. 用绿色集合式概率偏置完成多轮嵌入，再用二项假设下的 z 检验完成检测。
5. 在社交媒体模拟中改变用户画像，证明当前设置下检测信号不依赖特定情绪与活跃度。
6. 在讨论中承认动作自然性、更多场景和对抗攻击仍需后续研究。

其写作优点是问题、抽象和算法能够快速对应，读者容易理解“为什么要给行为加水印”。不足在于从概念可行性直接跳到“鲁棒、实用”的表述，中间缺少效用与安全证据。更完整的论文应先定义严格攻击面和效用约束，再给出统计校准、基线比较、消融以及跨环境实验。

# Watermarking LLM Agent Trajectories（ActHook）

## 0. 摘要

本文研究高价值 LLM Agent 轨迹数据的版权保护问题。轨迹数据由用户任务、模型动作与环境观测交错组成，数据量通常只有约一至两千条，而且训练时只有动作 token 计算损失，因此普通文本水印或代码语法变换很难被下游 Agent 稳定学到。作者提出 **ActHook**：在原轨迹的动作边界插入一个不改变任务结果的辅助动作，并在用户输入中加入秘密 key。若嫌疑模型使用过带水印轨迹训练，它在含 key 的查询上将显著提高 hook action 的出现率；所有权方因而可以通过黑盒查询完成检测。

ActHook 的核心不是隐藏一段固定文本，而是让模型学习“在特定触发条件下多执行一个合理动作”的行为关联。论文在数学推理、网页搜索与软件工程三类 Agent 上验证该思路，Qwen-2.5-Coder-7B 的平均检测 AUC 为 94.3，同时任务性能基本不变。论文已发表于 ICML 2026，并公开了代码。

## 1. 研究背景与问题定义

### 1.1 为什么 Agent 轨迹值得保护

高质量轨迹需要任务设计、强模型生成、环境执行和人工过滤。相比普通问答数据，轨迹还包含工具调用顺序、失败恢复和环境反馈等程序性知识；用少量专家轨迹进行行为克隆，就可能显著提高下游 Agent 能力。因此，数据所有者希望在不暴露训练过程和模型参数的情况下，判断某个黑盒 Agent 是否使用了自己的轨迹。

一条轨迹可写为：

$$\tau=\{x,(a_1,o_1),\ldots,(a_T,o_T)\}$$

其中 x 是任务输入，a 是 Agent 动作，o 是环境观测。行为克隆只在动作部分计算负对数似然：

$$\mathcal{L}=-\sum_{n=1}^{T}\log \pi_{\theta}(a_n\mid x,a_1,o_1,\ldots,a_{n-1},o_{n-1})$$

### 1.2 威胁模型

- 防御者可以在发布前修改少量轨迹，并保留秘密 key。
- 攻击者获得数据后进行微调，并仅向外提供黑盒 Agent 服务。
- 防御者不能读取权重或训练日志，只能提交查询并观察动作序列。
- 水印必须维持原任务正确性，并抵抗过滤、改写和动作摘要等数据清洗。

## 2. 核心洞见

作者观察到动作开头的 token 熵最高：模型首先要决定“下一步做什么”，一旦动作类型确定，后续命令或参数往往更容易预测。若在低熵的动作内部强行替换语法，少量水印样本很难压过预训练先验；若在高熵的动作边界插入一个来自原有动作空间的辅助动作，模型只需学习“何时执行”而不是记忆罕见字符串。

ActHook 因而把水印从 token 模式提升到行为模式。它只规定 hook 的语义，不固定其表面表达，使同一 hook 可以由不同命令或措辞实现。这既提高可学习性，也降低基于精确字符串搜索进行清洗的有效性。

## 3. 方法设计与复现级理解

### 3.1 水印方案的三个接口

一个水印方案 W 包含三个操作：

- `CHECK`：判断轨迹是否具备插入该 hook 的结构条件。
- `INJECT`：在保留全部原 action-observation 对的前提下插入新的 hook action 及其 observation。
- `DETECT`：根据输出动作的语义判断 hook 是否出现。

注入后轨迹比原轨迹多一个动作—观测对，但原有执行链不被删除或替换，因此设计目标是“不改变任务结果”。

### 3.2 两类 hook action

**Standalone hook** 不依赖局部上下文，可放在多个位置。例如数学 Agent 查询库版本、网页 Agent 访问 google.com、代码 Agent 执行 `pwd` 或查看 Python 版本。这类模式容易生成和学习，但异常动作更可能被观察者注意。

**Contextual hook** 依赖前一步动作。例如在搜索后访问第一条 URL，或在创建文件后执行 `ls -la`。它与轨迹上下文更自然，但只有满足特定结构的轨迹才能注入，候选覆盖率更低。

### 3.3 三阶段注入流程

第一阶段遍历全部轨迹，通过 `CHECK` 得到可注入集合。第二阶段根据水印比例 R 计算目标数量，并只从合法候选中抽样：

$$N_w=\lfloor R\lvert\mathcal{T}\rvert\rfloor$$

第三阶段使用辅助 LLM 生成多样化 hook action，将其插入选中轨迹，并把语义中性的秘密 key 追加到用户输入。最终训练关联不是“看到某类任务就执行 hook”，而是“看到 key 时提高执行 hook 的概率”。过滤后再抽样的顺序很重要：若先抽样再检查，contextual hook 的实际注入比例可能明显低于目标值。

### 3.4 黑盒检测流程

对 N 个测试任务，防御者分别提交含真实 key、无 key以及含 sham key 的查询，每种设置重复 Q 次。对第 i 个任务，hook 出现率为：

$$\hat q_{i,k}=Q^{-1}\sum_{j=1}^{Q}\hat h_{i,k,j}$$

聚合真实 key 与无 key 条件，得到水印效应量：

$$\hat\Delta_q=\hat q_k-\hat q_c$$

其中较大的正值意味着 key 显著提高 hook 行为概率。为了排除“任意附加短语都会改变模型行为”的混淆，论文引入从未参与训练的 sham key，并对每个任务构造配对差值：

$$d_i=\hat q_{i,k}-\hat q_{i,\tilde k}$$

最终执行单侧配对 t 检验：

$$t=\frac{\bar d}{s_d/\sqrt N},\qquad p=1-F_{N-1}(t)$$

### 3.5 样本复杂度

若真实 key 与无 key 的总体 hook 率差为正，满足给定假阳性率和假阴性率所需查询数近似为：

$$n\geq\frac{\left(z_{1-\alpha}\sqrt{q_c(1-q_c)}+z_{1-\beta}\sqrt{q_k(1-q_k)}\right)^2}{(q_k-q_c)^2}$$

这说明检测成本与效应量平方成反比：水印只产生很小的行为差异时，黑盒验证会迅速变贵。

## 4. 实验设置

| 项目 | 配置 |
|---|---|
| 任务域 | MATH 数学推理、SimpleQA 网页搜索、SWE-Smith 软件工程 |
| 训练轨迹 | 分别抽取 1,000、2,000、2,000 条正确轨迹 |
| Agent 框架 | MATH/SimpleQA 使用 Smolagents；SWE-Smith 使用 SWE-Agent |
| 评测 | Smolagents-Benchmark-v1 与 SWE-Bench Lite |
| 主检测模型 | Qwen-2.5-Coder-7B |
| 水印比例 | 重点考察 5% 与 10% |
| 对照 | CodeMark、无水印模型、sham key |

三个任务分别设计 standalone 与 contextual 水印。论文同时报告任务成功率、hook 检测器的 precision/recall/F1、激活差值、AUC、t 值和 p 值。

## 5. 主要实验结果

### 5.1 检测效果

ActHook 在 Qwen-2.5-Coder-7B 上取得平均 AUC 94.3。以 5% 水印比例为例，MATH standalone/contextual 的 AUC 为 97.3/95.8，SimpleQA 为 98.8/88.3；直接移植 CodeMark 时相应 AUC 多数接近随机水平。结果支持论文的核心判断：对短小 Agent 数据集，动作边界的行为水印比动作内部语法水印更容易被学习。

### 5.2 功能保持

hook action 是附加动作而非结果替换，正常无 key 查询基本保持原任务表现。这里的“无害”仍依赖环境：检查版本、访问网页或列目录在实验沙箱中副作用很小，但在计费 API、带权限工具或有状态生产系统中未必完全免费。

### 5.3 去除攻击

论文考察数据过滤、改写和动作摘要等攻击，攻击后 AUC 仍高于 85。原因在于检测关注 hook 的语义行为，而不是固定 token 串。不过，这些攻击主要作用于训练数据；更强的攻击者若知道候选 hook 类别，可针对特定辅助动作进行语义级删除。

## 6. 消融与参数理解

- 水印比例越高，模型越容易学会 key-hook 关联，但数据异常性和可检测性也越高。
- standalone hook 通常比 contextual hook 更容易学习；contextual hook 更自然，但依赖合法插入位置。
- 增加 N 或 Q 能降低检测方差，却会线性增加黑盒查询成本。
- sham key 对照不可省略，否则无法区分水印关联与提示词扰动效应。

## 7. 与相关方法的区别

| 方法 | 水印载体 | 是否需要触发 key | 检测对象 | 主要弱点 |
|---|---|---:|---|---|
| 文本生成水印 | 输出 token 分布 | 否 | 单段文本 | 不覆盖工具行为，易受改写影响 |
| CodeMark | 代码语法模式 | 通常是 | 代码 token | 小规模 Agent 轨迹上可学习性弱 |
| 普通后门 | 固定异常目标 | 是 | 触发后的目标输出 | 可能破坏任务功能 |
| ActHook | 附加 hook action | 是 | key 引起的行为频率增量 | 依赖可安全插入的辅助动作 |

## 8. 贡献与优点

1. 首次针对 Agent 训练轨迹提出行为级数据水印，并明确适配 action-observation 交错结构。
2. 将注入位置与动作边界的高熵性质联系起来，解释了少量水印样本为何仍可学习。
3. 采用真实 key、无 key 与 sham key 的配对检测，避免把普通提示扰动误判为水印。
4. 同时覆盖数学、搜索和代码 Agent，且提供正式代码与详细附录。

## 9. 局限性与批判性分析

1. **秘密 key 暴露后容易被规避。** 服务方可以过滤 key、对 key 做归一化，或对相关动作施加规则抑制。
2. **功能等价不等于生产安全。** 多执行一次网页访问、目录扫描或依赖查询会增加时延、费用和审计痕迹；某些工具调用还可能产生副作用。
3. **检测样本并非完全独立。** 同一任务的多次采样、同一模型的输出以及共享脚手架会形成相关性，简单 t 检验的独立性近似需要更谨慎验证。
4. **所有权与因果归因有距离。** 检出 key-hook 关联能说明模型接触过相关模式，但若攻击者独立构造相同模式或多个数据源共享 hook，法律意义上的所有权证据仍需额外链路。
5. **自适应攻击不足。** 论文主要验证通用清洗；已知算法、已知 hook 空间、蒸馏和再训练后的效果仍需系统评估。

## 10. 复现建议

1. 先复现单一任务域和 standalone hook，验证无 key 情况的任务性能与自然 hook 率。
2. 固定候选轨迹集合与随机种子，分别记录计划水印数和实际成功注入数。
3. hook 检测应采用语义规则并进行人工抽检，报告误检与漏检，而不是只给最终 AUC。
4. 检测集必须与训练轨迹去重，并预先固定真实 key、sham key、N、Q 和显著性阈值。
5. 至少运行多次独立微调，报告模型间方差；单一训练实例上的高 AUC 不能代表稳定归因能力。

## 11. 可延伸研究方向

- 设计无需显式文本 key、由工具状态或多轮上下文触发的水印。
- 将单一 hook 扩展为纠错编码的多 hook 指纹，用于区分不同授权用户。
- 研究多数据源混合、模型合并、蒸馏及持续训练后的水印存活率。
- 用顺序相关的统计量代替独立 hook 计数，提高对删除与重排的鲁棒性。
- 将安全副作用、额外 token、工具费用和执行时延纳入统一效用约束。

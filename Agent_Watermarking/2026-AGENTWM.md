# AGENTWM：面向灰盒智能体模仿攻击的动作轨迹水印

> 论文：**On Protecting Agentic Systems' Intellectual Property via Watermarking**  
> 方法：**AGENTWM**  
> 作者：Liwen Wang, Zongjie Li, Yuchong Xie, Shuai Wang, Dongdong She, Wei Wang, Juergen Rahmel  
> 单位：The Hong Kong University of Science and Technology；HSBC  
> 状态：arXiv:2602.08401，2026 年预印本

## 0. 摘要翻译

大语言模型正从文本生成器演化为能够自主推理和调用工具的智能体系统，这些系统由此产生了显著的知识产权价值。论文首先证明智能体很容易受到模仿攻击：攻击者收集受害系统的输出，再用这些数据训练模仿模型，即可窃取其专有能力。现有 LLM 水印难以直接解决这一问题，因为现实智能体往往采用灰盒服务模式，只公开工具调用等动作轨迹，而隐藏水印检测所需的内部推理过程。

论文提出 AGENTWM，一种专门面向智能体模型的水印框架。其核心是利用动作序列之间的语义等价性：同一任务可以通过不同供应商的工具、不同接口别名或不同但功能等价的调用组合完成。AGENTWM 在这些等价执行路径之间施加轻微的分布偏置，把可验证信号写入用户可见的动作轨迹，同时尽量维持原有功能。作者设计了自动生成和验证等价动作集合的流水线，并通过基于 Jensen–Shannon 散度与多水印计数的统计流程验证模型窃取及定位恶意用户。三个领域的实验表明，该方法检测 F1 可达到 1.0，推理延迟增量为 0.28%，而具备水印知识的攻击者若试图大范围移除水印，会显著降低轨迹质量。

## 1. 方法动机

### 1.1 智能体知识产权为何不同于普通 LLM

现代智能体的价值不只来自模型能够回答问题，还来自它学会了如何选择工具、组织调用顺序并完成长程任务。高质量工具轨迹通常通过专用数据、监督微调和强化学习获得，因此本身就是可被窃取的程序性能力。

论文展示了一个直接的模仿攻击：攻击者查询受害智能体，收集只包含动作和最终回复的灰盒轨迹，再用辅助 LLM 重构隐藏推理并微调公开骨干模型。实验中，原始 Qwen3-4B 的 PR、RS、TS 分别为 0.418、0.339、0.596；模仿后提高到 0.652、0.547、0.834，接近受害模型的 0.687、0.574、0.903。说明仅保护权重并不能阻止能力通过服务接口被复制。

### 1.2 为什么文本水印不够

作者调查了 29 个商业智能体平台，其中 24 个采用灰盒可见性：隐藏 thought 和 observation，只向用户公开工具动作序列及最终回复。此时存在三个问题：

1. 最终回复可能很短，缺少文本水印所需的 token 数量。
2. 中间推理不可见，无法在验证时访问其中的水印。
3. 工具调用具有严格语法，直接修改 token 可能导致调用失败。

因此，水印必须存在于公开、可执行并能被模仿模型学到的 **动作轨迹层**。

### 1.3 核心观察：轨迹等价性

同一个功能经常有多种等价实现：Gmail 与 Outlook 都能发邮件，接口 V1 和 V2 可能指向同一后端，移动文件既可用一个原子工具，也可通过复制加删除实现。这些差异不改变任务语义，却形成了天然的离散水印信道。

AGENTWM 不把某个固定动作当作触发器，而是改变一组等价动作在大量轨迹中的出现频率。模仿模型用这些轨迹训练后，会继承这种统计偏好。

## 2. 威胁模型

### 2.1 灰盒服务设定

一次完整轨迹由多个 thought–action–observation 步骤与最终回复组成，但用户只看到：

$$\widetilde{\tau}=(\mathbf{a},r)$$

其中 `a` 是动作序列，`r` 是最终回复。内部思维和环境观察均被平台隐藏。所有者和攻击者都基于公开骨干模型开发系统；所有者使用私有高质量轨迹训练受害模型，攻击者通过 API 收集受害输出并训练模仿模型。

### 2.2 攻击者目标与能力

攻击者希望复制受害模型的领域能力，避免付费或建立竞争服务。论文给予攻击者较强能力：它可以大量查询受害系统，取得灰盒轨迹，并使用辅助 LLM 重构隐藏内容，再微调相同或不同的公开骨干模型。

### 2.3 两种水印知识水平

- **部分知情攻击者 PK**：知道服务存在水印，但不知道五类水印方案及具体实例。
- **完全知情攻击者 FK**：知道所有五类方案，但不知道目标用户被分配了哪些具体 watermark pass、目标动作和偏置配置。

论文的“完全知情”并不等于密码学意义上的最强攻击者。FK 攻击者仍不知道用户 pass 集合，也不能访问私有验证集和注册表；论文没有评估多用户串谋、验证器反馈查询、服务端 pass 泄漏或精确分布估计攻击。

### 2.4 验证假设

所有者能够黑盒查询可疑模型，并持有一个与受害训练数据同分布但不公开的验证集。验证者还必须知道每个 pass 的目标分布和所有用户的 pass 分配。若真实部署中的查询分布发生偏移，目标动作很少出现，或者可疑模型不返回可分析的动作轨迹，验证能力会下降。

## 3. 方法设计与复现级理解

### 3.1 系统分为离线准备、在线插入和事后验证

AGENTWM 不是修改模型权重，而是部署在智能体生成原始轨迹之后、轨迹返回用户之前：

1. **离线准备**：从工具库发现候选等价动作，验证功能等价性，生成 watermark pass 池。
2. **在线插入**：根据用户 UID 激活一组 pass；若轨迹命中某个等价动作集合，就按偏置分布替换为等价成员。
3. **事后验证**：查询可疑模仿模型，统计等价动作频率，检测它是否继承了目标分布，并与用户注册表匹配。

### 3.2 Watermark pass 的定义

一个 pass `P_i` 对应一个等价动作片段集合：

$$\mathcal{E}_i=\{w_1,w_2,\ldots,w_k\}$$

集合成员可以是单个工具调用，也可以是多动作子序列。它们应当实现相同功能。训练数据中这些成员原本服从自然分布 `D_i`，AGENTWM 将其变为带偏置目标分布 `Dhat_i`。

如果原轨迹包含 `E_i` 中的某个片段，系统不删除这一功能，而是重新从同一等价集合中采样替代片段。因此水印载体不是某个异常 token，而是不同合法实现方式的总体频率。

### 3.3 目标分布如何构造

对每个等价集合，选择一个目标成员 `w_t`，给它的 logit 增加偏置 `delta`。归一化常数为：

$$Z=p(w_t)e^{\delta}+\sum_{j\ne t}p(w_j)$$

目标成员的新概率为：

$$\widehat p(w_t)=\frac{p(w_t)e^{\delta}}{Z}$$

其他成员的新概率为：

$$\widehat p(w_j)=\frac{p(w_j)}{Z},\qquad j\ne t$$

`delta` 越大，目标动作出现得越频繁，越容易被后续模型学到和检测；但分布漂移也越明显，可能破坏隐蔽性和语义质量。论文建议实际使用 `delta=2` 到 `3`。

### 3.4 用户指纹如何映射到 pass

假设某领域共有 `N` 个 pass，为每个用户分配随机且不可预测的 `N` 位 UID：

$$U_{id}\in\{0,1\}^N$$

第 `i` 位为 1 时激活第 `i+1` 个 pass。用户实际 pass 集合为：

$$\mathcal{P}_{id}=\{P_{i+1}\mid U_{id}[i]=1\}$$

作者把 UID 的汉明重量限制在 5 到 20，即每个用户只激活部分 pass。对 Data 域的 39 个 pass，可用组合数为：

$$C=\sum_{k=5}^{20}\binom{39}{k}\approx3.43\times10^{11}$$

这个数字代表理论组合空间，不等于同规模用户下仍能可靠定位。不同 UID 可能具有较高重叠，而实际定位还受到 pass 命中率、训练继承和检测错误影响。论文在 5 万用户池上的 Social 域 Top-1 已下降到 0.81。

### 3.5 在线轨迹改写

对某个用户请求，智能体先产生原始动作序列。AGENTWM 扫描其中是否包含已激活 pass 的任意等价片段。一旦命中，就按对应目标分布重新采样并替换；若多个 pass 相互影响，则按固定顺序执行，以保证训练与验证定义一致。

需要关注一个部署语义问题：论文描述的是“生成原始轨迹后、返回用户前”替换动作。如果原动作已经真实执行，只改写展示日志会造成公开账单轨迹与实际执行不一致；如果替换后重新执行，则可能增加调用成本或产生不可逆副作用。实验通过沙箱和模拟环境验证等价性，但真实有状态 API 中的事务、权限、计费和时序等价仍需单独保证。

### 3.6 五类等价水印

| 类别 | 名称 | 等价来源 | 示例 |
|---|---|---|---|
| 动作级 | Vendor Replacement | 不同厂商提供相同功能 | Gmail.SendEmail 与 Outlook.SendEmail |
| 动作级 | Parameter Granularity Replacement | 参数抽象粒度不同但结果一致 | 结构化邮件字段与自然语言邮件指令 |
| 动作级 | Interface Aliasing | 同一后端的版本、地区或别名接口 | API_V1 与 API_V2 |
| 结构级 | Auxiliary Equivalence | 主操作与附加只读辅助操作组合 | BookFlight 与 BookFlight + GetConfirmation |
| 结构级 | Compositional Equivalence | 原子操作与等价复合序列 | MoveFile 与 CopyFile + DeleteFile |

前三类只替换单个工具调用，后两类改变调用子序列结构。多类方案扩大了攻击者需要枚举的变换空间，但“功能等价”必须包含副作用、异常行为、权限和计费，而不能只比较正常输入下的最终输出。

### 3.7 自动生成 watermark pass

作者使用 xlam-function-calling-60k 中的 3673 个工具作为候选库，采用两阶段流程：

**阶段一：Generator 候选挖掘。** 先用 Qwen3-Embedding 计算工具语义相似度，删除明显无关的组合；再用 LLM 按五种方案判断潜在等价关系，得到约 207 组候选。

**阶段二：Verifier 等价验证。** 使用另一个 LLM 检查语义，再在沙箱中用多组输入真实执行候选片段，比较输出和副作用。只有同时通过语义与执行验证的候选才注册为 pass。最终获得 101 个 pass；作者还人工抽查其中 50 个，未发现功能不一致。

101 个 pass 的构成为：VR 38 个、PGR 13 个、IA 22 个、AE 15 个、CE 13 个；Data、Business、Social 三个领域分别有 39、28、34 个。

### 3.8 单个 pass 的检测

验证者使用私有验证集查询可疑模型，收集动作轨迹，并计算等价集合中各成员的经验分布 `D'_i`。再将其与水印目标分布 `Dhat_i` 比较。令二者均值分布为：

$$M_i=\frac{D'_i+\widehat D_i}{2}$$

Jensen–Shannon 散度为：

$$JSD(D'_i,\widehat D_i)=\frac{1}{2}KL(D'_i\Vert M_i)+\frac{1}{2}KL(\widehat D_i\Vert M_i)$$

当散度小于阈值 `theta_J` 时，判定该 pass 被可疑模型继承：

$$z_i=\mathbf{1}[JSD(D'_i,\widehat D_i)<\theta_J]$$

### 3.9 整体模型判定

系统不会因为一个 pass 偶然匹配就指控模型窃取，而是统计所有被检测的 pass：

$$n_{det}=\sum_{i=1}^{N}z_i$$

只有满足：

$$n_{det}\ge\theta_N$$

才把可疑模型判为模仿模型。`theta_J` 控制单 pass 灵敏度，`theta_N` 控制需要多少个独立信号共同出现。实验推荐 `theta_N=3`。

论文把这一过程称为统计假设检验，但没有从明确零假设推导 p-value 或对多重 pass 检验做显著性校正；阈值主要通过有限模型样本经验选择。因此它更准确地说是“双阈值统计分类器”，而不是具有预先保证错误率的经典假设检验。

### 3.10 恶意用户定位

检测结果构成一个 `N` 维二进制向量：

$$\mathbf v=(z_1,z_2,\ldots,z_N)$$

将它与用户注册表中的 UID/pass 向量 `p_u` 计算余弦相似度：

$$sim(\mathbf v,\mathbf p_u)=\frac{\mathbf v\cdot\mathbf p_u}{\|\mathbf v\|_2\|\mathbf p_u\|_2}$$

相似度最高的用户被视为数据泄露来源。采用相似匹配而不是精确匹配，是为了容忍部分 pass 没有被模仿模型学到。但随机分配 UID 不保证最小码距；若要扩展到极大用户池，更合理的方式是显式设计具有距离约束的指纹码并考虑串谋追踪。

## 4. 与 Agent Guide 和 AgentMark 的区别

| 方法 | 嵌入时机 | 水印载体 | 是否保持原分布 | 主要目标 | 验证所需信息 |
|---|---|---|---:|---|---|
| Agent Guide | 规划采样时 | 高层行为绿色集合频率 | 否 | 行为水印存在性 | 行为、轮次和密钥 |
| AgentMark-F | 规划采样时 | 密钥控制的行为选择 | 对显式规划分布保持 | 多比特 Agent 身份 | 行为、概率列表、上下文和密钥 |
| AGENTWM | 轨迹生成后或动作输出层 | 功能等价动作及动作子序列分布 | 否，主动偏置等价实现 | 证明模仿训练并定位泄露用户 | 可疑模型、私有查询集、目标分布和 pass 注册表 |

AgentMark 标记“这条轨迹由哪个启用水印的 Agent 产生”；AGENTWM 更关注“这个可疑模型是否用某个用户取得的水印轨迹训练过”。前者是生成时多比特编码与日志解码，后者是训练数据污染式指纹继承与模型归属验证。

AGENTWM 的优势是只依赖灰盒可见动作，不需要模型显式输出规划概率；代价是必须改变动作实现分布，而且需要足够多的训练样本让模仿模型学到偏置。

## 5. 实验设置与结果解读

### 5.1 数据、模型与资源

| 项目 | 配置 |
|---|---|
| 原始数据 | xlam-function-calling-60k，6 万轨迹、3673 个工具、21 个领域 |
| 实验领域 | Data、Business、Social |
| 整理后规模 | 3 万轨迹：2.4 万训练、6000 测试 |
| 骨干模型 | 主实验 Qwen3-4B；泛化实验 Qwen3-8B、Ministral-8B |
| Agent 框架 | ReAct |
| 环境模拟器 | Qwen3-Next-80B-A3B |
| 微调 | LoRA rank 64，alpha 128，学习率 2e-4 |
| 评测 Judge | DeepSeek-v3.2 |
| 硬件 | 4 张 NVIDIA H800 |
| 水印 | 5 类、101 个 pass；每用户激活 5–20 个 |

### 5.2 模仿攻击有效性

| 模型 | PR | RS | TS |
|---|---:|---:|---:|
| 受害模型 | 0.687 | 0.574 | 0.903 |
| 原始公开模型 | 0.418 | 0.339 | 0.596 |
| 模仿模型 | 0.652 | 0.547 | 0.834 |

模仿模型的三个指标均明显接近受害模型，说明灰盒轨迹确实包含可迁移的工具使用能力。这一实验支撑了问题动机，但只展示一种数据构造和训练方案，尚不能说明所有商业智能体都有相同可提取性。

### 5.3 保真度

作者比较受害模型与使用水印轨迹训练的模仿模型。在 Data 域，受害模型 PR 为 0.792，三种水印数量下的模仿模型 PR 为 0.755、0.703、0.741；Business 域为 0.687 对 0.642、0.637、0.664；Social 域为 0.707 对 0.678、0.663、0.626。

这些结果说明水印数据仍能训练出有效模型，但不能直接证明“水印只造成不超过 3% 的退化”。受害模型与模仿模型之间同时存在灰盒重构、训练随机性和容量差异；部分 PR 差距明显超过 3 个百分点，例如 Data 的 0.792 对 0.703、Social 的 0.707 对 0.626。更严格的水印保真度实验应比较同一训练设置下的 clean imitation 与 watermarked imitation，而不是主要与 victim 比较。

### 5.4 通用能力与开销

ARC 和 ACPBench 上，水印模仿模型大体保持通用推理与规划能力。例如 Data 域受害模型 ARC 为 80.43%，10–15 pass 的模仿模型为 80.09%。在线插入 1000 个查询额外消耗 9.6 秒，而总响应时间为 3428 秒，即 0.28% 增量。

该低开销建立在“只扫描和替换动作序列，不额外调用 LLM”的实现上；离线 pass 生成、沙箱执行和验证查询成本不计入在线延迟。

### 5.5 窃取检测

作者在三个领域共训练 36 个带水印模仿模型，并为每个领域准备 12 个干净负样本模型；扫描五个 JSD 阈值和 1–5 的 pass 数量阈值。在合适设置下 F1 接近或达到 1.0，推荐 `theta_N=3`。

但每个领域只有 12 个正样本和 12 个负样本。如此小的模型级样本量无法精确估计低 FPR，也容易使阈值选择对当前数据过拟合。论文还使用 `D_test` 作为任务测试集和私有验证集；真实部署应使用独立、从未参与阈值选择的验证查询。

### 5.6 用户定位

| 用户池规模 | Data | Business | Social |
|---:|---:|---:|---:|
| 12 | 1.00 | 1.00 | 0.92 |
| 12 + 1K | 1.00 | 1.00 | 0.92 |
| 12 + 2K | 0.97 | 1.00 | 0.89 |
| 12 + 5K | 0.97 | 0.97 | 0.86 |
| 12 + 50K | 0.92 | 0.94 | 0.81 |

随着用户池扩大，随机 UID 之间的 pass 重叠增加，Social 域下降最明显。理论上 3430 亿组合不代表可以在 3430 亿用户中保持同等定位精度；真实容量由最小指纹距离、pass 可观测率和检测噪声共同决定。

### 5.7 去水印攻击

部分知情攻击者使用随机删除、LLM 改写和 LLM 替换来猜测并移除水印位置，其“识别水印 token”的 F1 分别为 0.0103、0.0023 和 0.0040。完全知情替换攻击的 F1 提高到 0.2350，但修改后 RS 从 0.612 降至 0.391，TS 从 0.877 降至 0.514。

这里必须谨慎解释：论文报告的主要攻击指标是攻击者能否识别水印 token，而 AGENTWM 实际水印单位是动作或动作子序列分布。低 token 定位 F1 并不自动等于最终模型水印仍能被检测。更有说服力的评测应是：攻击轨迹后重新训练模仿模型，再运行完整 JSD/pass-count 验证，报告检测 TPR、FPR 和攻击后模型效用。正文没有系统给出这条完整闭环。

### 5.8 隐蔽性

作者用 GPT-2 计算水印前后轨迹的困惑度，平均差小于 0.5且密度曲线接近重合。这只能说明文本表面流畅度相近。AGENTWM 的检测信号本来就是工具供应商、接口别名和调用结构频率，因此真正相关的隐蔽性攻击应分析 action n-gram、供应商选择、调用长度和结构分布，而不是主要依赖自然语言 PPL。

### 5.9 水印强度消融

| `delta` | 1 | 2 | 3 | 4 | 5 |
|---:|---:|---:|---:|---:|---:|
| KLD | 0.096 | 0.386 | 0.801 | 1.408 | 1.808 |
| TS | 0.712 | 0.712 | 0.707 | 0.694 | 0.671 |

偏置增强会快速扩大分布差异，并逐渐降低轨迹质量。`delta=2–3` 是作者推荐区间，但论文没有同时在同一表中给出该区间对应的检测样本量和固定 FPR 下 TPR，因此完整的检测–质量 Pareto 前沿仍不清楚。

### 5.10 跨骨干模仿

当受害模型使用 Ministral-8B 或 Qwen3-8B、攻击者使用 Qwen3-4B 时，模仿模型仍能接近受害性能：PR 分别为 0.661 对 0.702、0.689 对 0.742。这说明能力窃取和水印偏好可能跨架构迁移。不过论文提供的可靠性结果主要是用户定位准确率，缺少不同骨干组合下完整的检测 ROC。

## 6. 可学习与可应用的思想

### 6.1 利用语义等价空间承载训练数据指纹

AGENTWM 最有价值的思想是：当输出必须保持功能正确时，不必修改文本内容，可以在多个合法实现之间编码统计偏好。这个思想适用于代码 API、SQL 查询计划、工作流节点、路由选择和智能体工具链。

### 6.2 用户级差异化水印

每个用户获得不同 pass 子集，使模型窃取检测与泄露源定位统一起来。相比所有用户共享同一水印，这种设计更适合 API 服务。进一步工作应使用具备最小汉明距离和抗串谋性质的指纹码，而不是完全随机选择 pass。

### 6.3 自动等价验证流水线

先用表示模型和 LLM 高召回挖掘候选，再用独立 LLM、沙箱执行和人工抽查提高精度，是将语义水印落地到大规模工具库的实用路径。安全场景中还应加入属性测试、异常输入、并发、权限、回滚和费用一致性检查。

### 6.4 对语音智能体的启发

语音 Agent 也存在等价执行路径，例如不同 ASR/TTS 服务商、相同能力的工具接口、等价的确认与澄清流程。可以把用户指纹写入服务选择和对话策略分布，并与波形水印组合。不过必须避免让用户身份影响服务质量、公平性或隐私，并防止攻击者通过供应商频率轻易反推指纹。

### 6.5 建议的后续改进

- 对每个 pass 建立正式的等价规范与属性测试，而不只依赖正常样例。
- 使用秘密控制的分布保持编码，减少 `delta` 引起的可检测频率漂移。
- 设计抗串谋用户码，评估多个账号合并数据后的定位能力。
- 使用独立校准集建立每个 pass 的零分布，并对多重检验控制整体 FPR。
- 报告查询数量与检测功效曲线，明确每个 pass 至少需要多少命中样本。
- 评估攻击后重训练的完整闭环，而不是只测水印位置识别 F1。
- 针对 action 频率和结构训练专门的水印检测器，替代不匹配的 GPT-2 PPL 隐蔽性指标。

## 7. 一句话总结

**AGENTWM 通过偏置功能等价工具调用及调用子序列的出现分布，把用户指纹写入灰盒可见动作轨迹并让模仿模型继承该偏好，从而实现模型窃取检测和泄露用户定位，但其统计检验、真实 API 等价性、隐蔽性指标和攻击后端到端验证仍有明显完善空间。**

## 9. 复现难度

### 9.1 难度判断

**高。** 单个分布偏置和 JSD 检测容易实现，但完整复现需要构建 3 万条多步轨迹、部署环境模拟器、生成并执行验证数千个工具组合、训练数十个模仿模型，并消耗论文所述约 1000 GPU 小时完成可靠性实验。目前未找到官方代码，进一步增加了复现成本。

### 9.2 最小方法复现

1. 选择一个含冗余工具的领域，定义 5–10 个等价集合。
2. 在沙箱中对正常、异常和边界输入验证输出与副作用等价。
3. 从干净轨迹估计每个集合的自然分布 `D_i`。
4. 选择目标成员和 `delta`，计算 `Dhat_i`。
5. 为用户生成具有明确最小距离的 pass 指纹，而非纯随机组合。
6. 对轨迹做固定顺序匹配和等价替换。
7. 分别用 clean 与 watermarked 轨迹训练同配置模仿模型。
8. 使用独立校准集确定 `theta_J` 和 `theta_N`，再在保留测试集报告 ROC 与固定 FPR TPR。
9. 完成“攻击轨迹→重新训练→再次验证”的端到端去水印评测。

### 9.3 复现关键风险

- 自然分布估计样本过少会使 JSD 检测不稳定。
- 等价工具在速率限制、权限、费用或异常条件下可能并不等价。
- 多个 pass 连续应用时可能改变后续匹配候选，必须固定顺序。
- 验证查询若与训练分布偏移，目标动作可能不出现。
- 用同一测试集调阈值和报告结果会高估检测性能。
- LLM judge、轨迹重构器和环境模拟器本身会引入系统性偏差。

## 10. 300–500 字总结

AGENTWM 面向灰盒智能体服务中的模型窃取问题。作者观察到多数商业平台隐藏推理与观察，只公开工具调用和最终回复，因此普通文本水印难以验证；另一方面，同一任务通常可由不同厂商工具、接口别名、参数粒度或等价调用组合完成。AGENTWM 将这些功能等价片段组成 watermark pass，通过 logit 偏置提高某个目标实现的出现概率，并为每个用户分配不同的 pass 子集。攻击者若利用带水印轨迹训练模仿模型，模型会继承相应动作分布；所有者再用私有查询集统计各 pass 的经验分布，通过 JSD 阈值和检测 pass 数量判断模型窃取，并与用户注册表做余弦匹配定位泄露账号。论文从 3673 个工具中自动挖掘、语义验证和沙箱执行，最终得到五类 101 个 pass。主实验显示在线延迟仅增加 0.28%，合适阈值下检测 F1 接近 1，在 5 万用户池中定位准确率为 0.81–0.94。其亮点是直接适配用户可见动作轨迹并支持用户级追踪；局限是等价关系在真实有状态 API 中未必成立，检测阈值缺少严格错误率校准，PPL 隐蔽性指标与动作分布不匹配，去水印实验也未完整展示攻击、重训练和最终验证的闭环。因此它是一套很有实践启发的轨迹数据指纹框架，但距离可直接用于法律归属证明仍需更严格统计和真实部署验证。

## 11. 论文写作逻辑

论文采用“现实缺口—攻击证明—系统设计—五维评估”的结构：

1. 先说明智能体的 IP 已从人工编排转移到模型内化的工具使用能力。
2. 用 29 个商业平台调查建立灰盒可见性假设，再用模仿实验证明动作轨迹足以窃取能力。
3. 从轨迹等价性提出水印信道，将水印定义为等价动作集合内部的分布偏置。
4. 将方法拆为 pass 生成、用户指纹分配、在线替换和可疑模型验证。
5. 用五类等价方案说明框架具有领域泛化空间，再用自动挖掘和双重验证解决人工构造成本。
6. 按 Fidelity、Reliability、Robustness、Stealthiness、Cost 和 Ablation 组织实验，覆盖论文开头提出的设计目标。

优点是工程故事完整，攻击场景、用户级追踪和自动 pass 生成结合紧密。问题在于若干强结论超过了直接证据：经验双阈值被表述成严格假设检验，token 定位失败被等同为水印不可移除，PPL 重合被等同为动作分布不可检测，而小规模模型样本上的 F1=1 也不足以支撑法律级低误报声明。

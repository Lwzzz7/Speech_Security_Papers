# AgentMark：兼顾效用与鲁棒性的智能体行为水印

> 论文：**AgentMark: Utility-Preserving Behavioral Watermarking for Agents**  
> 作者：Kaibo Huang, Jin Tan, Yukun Wei, Wanling Li, Zipei Zhang, Hui Tian, Zhongliang Yang, Linna Zhou  
> 发表：ACL 2026 Main Conference，长文，pp. 12581–12603  
> 代码：[Tooooa/AgentMark](https://github.com/Tooooa/AgentMark)

## 0. 摘要翻译

基于大语言模型的智能体正越来越多地被部署用于自主完成复杂任务，因此知识产权保护与监管溯源变得十分迫切。内容水印能够有效标记 LLM 生成的最终输出，但无法直接识别控制多步执行过程的高层规划行为，例如工具选择和子目标选择。在规划行为层嵌入水印存在两个特殊困难：其一，决策分布的微小偏移可能在长期运行中不断累积，最终损害任务效用；其二，许多智能体以黑盒 API 形式运行，难以直接干预其模型内部。

为此，论文提出 AgentMark，一种在保持效用的同时将多比特标识符嵌入规划决策的行为水印框架。AgentMark 首先让黑盒智能体显式输出候选行为的概率分布，再采用保持该分布不变的条件采样方式编码水印，因此无需修改模型参数，同时能够与动作层的内容水印共存。论文进一步使用基于上下文的可复现随机性和随机线性网络编码，使验证者在日志缺失或轨迹被截断时仍可从剩余行为中恢复标识符。作者在具身任务、工具调用和社交仿真环境中验证了多比特容量、部分日志下的恢复能力和任务效用保持。

## 1. 方法动机

### 1.1 内容溯源无法等价替代行为溯源

智能体系统包含两个不同层次：

- **规划行为**决定下一步做什么，例如选择搜索工具、购票、支付或确定子目标。
- **执行动作**决定如何完成该行为，例如 API 参数、结构化调用格式或最终生成文本。

传统文本水印主要存在于执行动作的表面内容中。一旦规划结果被编译成 API 调用、数据库操作或环境动作，文本 token 可能消失，内容水印也无法说明智能体为何选择这条规划路径。因此，版权鉴定和监管审计需要直接标记规划行为序列。

### 1.2 为什么不能直接给行为概率加偏置

前作 Agent Guide 使用红绿集合和概率偏置，使某些行为更容易被选中。它可以产生明显统计信号，但也改变了原始策略分布。单步变化可能很小，长轨迹中却会通过环境反馈不断放大：一次偏离会改变下一步观察、历史和候选行为，最终导致任务失败或路径变长。

AgentMark 的关键目标不是“让某些行为出现得更多”，而是 **在行为选择的随机性中编码信息，同时保持每个行为原本的边际概率不变**。

### 1.3 论文试图同时满足的三个目标

1. **黑盒适配**：只依赖 LLM API 输出的候选行为与概率，不修改模型权重或内部 logits。
2. **效用保持**：水印行为在每一步仍服从显式行为分布，避免长期概率漂移。
3. **多比特与缺失鲁棒性**：从多轮轨迹中恢复所有者 ID，并容忍日志删除和轨迹截断。

## 2. 威胁模型

### 2.1 系统参与者

- **所有者或嵌入者**：持有共享密钥和多比特身份载荷，能够在规划输出与动作执行之间部署 AgentMark。
- **黑盒智能体**：根据观察和历史生成有限候选行为集合及其概率分布。
- **执行环境**：接收选中的规划行为，生成具体动作和下一步观察。
- **验证者**：持有共享密钥，能够获得部分规划日志，包括行为、相应概率分布和足以重建随机性的上下文。

### 2.2 论文正式建模的破坏

论文主要考虑验证日志不完整：

- **随机步骤擦除**：每个规划步骤以一定概率从日志中丢失。
- **轨迹截断**：验证者只能获得一段前缀或连续片段。
- **观察语义重写**：原始观察文本被同义改写，但环境状态不变，从而破坏编码器和解码器对上下文的同步。
- **错误密钥验证**：验证者使用不正确的密钥尝试恢复载荷。

### 2.3 未充分覆盖的自适应攻击

论文没有实证评估知道算法的攻击者如何主动选择删除位置、替换行为、篡改概率列表、伪造上下文或查询验证器。作者在附录中明确承认，当前实验以随机擦除、截断和非自适应语义改写为主，完整的自适应攻击仍属于未来工作。

### 2.4 安全边界

AgentMark 保护的是 **规划轨迹的来源与身份载荷**，并不保证智能体行为安全、任务结果正确，也不阻止攻击者删除全部日志。当可用记录不足以形成满秩线性方程组时，任何解码器都无法恢复载荷。

## 3. 方法设计与复现级理解

### 3.1 整体数据流

在第 `t` 步，智能体接收观察 `o_t` 和历史 `h_t`，候选规划行为集合为：

$$\mathcal{B}_t=\{b_{t,1},b_{t,2},\ldots,b_{t,n}\}$$

标准智能体隐式存在一个规划策略分布：

$$P_t^\star=\pi_\theta(\cdot\mid o_t,h_t)$$

由于黑盒 API 通常不给出规划 logits，AgentMark 通过提示词让模型显式返回候选行为及概率，得到近似分布：

$$P_t\approx P_t^\star$$

之后的完整路径为：显式概率诱导 → 差分重组 → 密钥采样均匀桶 → CyclicShift 编码 → 选择规划行为 → 生成执行动作 → 记录上下文与概率 → RLNC 聚合解码。

### 3.2 分布保持的准确含义

AgentMark 要求水印采样后的行为对每个候选项都保持原概率：

$$\Pr[\hat b_t=b\mid P_t]=P_t(b)$$

这个保证是相对于 **诱导得到的显式分布** `P_t`，不是对无法直接观察的真实隐式策略 `P_t^star` 的无条件保证。如果诱导提示改变了模型决策，或者模型报告的概率没有校准，算法仍能忠实保持 `P_t`，却不一定保持原始无诱导智能体的行为。

### 3.3 第一步：固定排序与差分切片

将候选行为按概率从高到低稳定排序：

$$p_1\ge p_2\ge\cdots\ge p_n,\qquad p_{n+1}=0$$

为避免概率相同时编码端和解码端排序不一致，论文先按固定精度量化概率，再使用稳定排序。随后定义相邻概率的差：

$$d_k=p_k-p_{k+1}$$

第 `k` 个均匀桶包含概率最高的前 `k` 个行为：

$$T_k=\{b_{t,1},b_{t,2},\ldots,b_{t,k}\}$$

该桶在混合分布中的权重为：

$$q_k=k d_k$$

直观上，这是把概率柱状图横向切成若干等高薄片：高度为 `d_k` 的一层同时覆盖前 `k` 个行为，因而该层的总质量是 `k d_k`。

### 3.4 为什么重组后仍保持原分布

编码器先按照权重 `q_k` 选择一个桶，再在桶内均匀选择行为。对排序后第 `i` 个行为，它只出现在所有 `k>=i` 的桶中，因此最终概率为：

$$\Pr[\hat b_t=b_{t,i}]=\sum_{k=i}^{n}q_k\frac{1}{k}=\sum_{k=i}^{n}(p_k-p_{k+1})=p_i$$

这一步是 AgentMark 区别于 Agent Guide 的核心：水印信息不是通过改变某些行为的总概率写入，而是通过密钥控制“均匀桶内部哪个索引对应哪段载荷”来编码。

### 3.5 第二步：用上下文派生每步随机性

编码端和验证端共享主密钥 `K_sh`。每一步根据主密钥和可重建上下文派生局部密钥：

$$K_t=H(K_{sh}\Vert Context_t)$$

`Context_t` 可以包含轮次、当前观察和近期历史。局部密钥初始化伪随机生成器，用于桶选择和桶内循环移位。这样不同步骤的随机性相互隔离，而且验证者不必保存每次随机数。

它同时形成一个脆弱点：如果验证端看到的观察或历史与嵌入端不同，即使语义相同，哈希结果也会完全变化，导致桶选择和位映射失步。

### 3.6 第三步：密钥控制的桶选择

伪随机生成器按照 `q_1` 到 `q_n` 的分类分布选择桶：

$$K\sim Cat(q_1,q_2,\ldots,q_n),\qquad T=T_K$$

桶大小决定这一轮最多能承载多少信息。若只选到单元素桶，行为没有选择自由度，容量为零；行为分布越平坦，高概率选中大桶，每步容量越高。

### 3.7 第四步：CyclicShift 变长编码

设选中桶大小为 `n`，令：

$$k=\lfloor\log_2 n\rfloor,qquad m=n-2^k$$

由于 `n` 不一定是 2 的幂，不能简单地为所有行为分配同长度码字。CyclicShift 构造前缀码：其中 `2^k-m` 个索引承载 `k` 位，其余 `2m` 个索引承载 `k+1` 位。再使用伪随机偏移 `R` 对码字和桶索引的对应关系做循环置换：

$$R=\lfloor u n\rfloor,qquad u\sim U[0,1)$$

编码器根据载荷前缀确定未移位索引，再加上 `R` 得到实际行为索引；解码器用相同密钥重建 `R`，执行逆移位即可取回比特。其期望容量为：

$$E[c\mid n]=k+\frac{2m}{n}$$

论文给出的容量界为：

$$\log_2 n-0.0861\le E[c\mid n]\le\log_2 n$$

因此，相对于一个大小为 `n` 的均匀选择信道，CyclicShift 与理论上限的差距至多约 0.0861 bit。

### 3.8 单步编码与解码流程

单步编码过程可以复现为：

1. 用固定精度量化并稳定排序 `P_t`。
2. 计算所有 `d_k`、均匀桶 `T_k` 和桶权重 `q_k`。
3. 从 `K_sh` 与 `Context_t` 派生 `K_t`，初始化伪随机生成器。
4. 按 `q_k` 采样桶 `T`。
5. 根据桶大小和待写入比特执行 CyclicShift，得到桶内索引 `j`。
6. 输出 `T[j]` 对应的规划行为，同时推进载荷指针。

验证端使用相同的 `P_t`、上下文和密钥重新构造桶，找到观测行为在桶内的索引，再用逆 CyclicShift 恢复该步的变长比特串。

### 3.9 为什么还需要 RLNC

直接顺序写入载荷时，删除一个步骤不仅丢掉对应比特，还可能使后续变长片段的边界全部错位。AgentMark 因此不直接发送原始 ID，而是把每个可嵌入比特视为一个随机线性方程。

设身份载荷为长度 `L` 的二进制向量：

$$m\in\mathbb{F}_2^L$$

在第 `t` 步第 `j` 个可用比特位置，由局部密钥生成系数向量：

$$a_{t,j}=PRG(K_t,j)\in\mathbb{F}_2^L$$

实际嵌入的比特是系数与载荷的二进制内积：

$$y_{t,j}=\langle a_{t,j},m\rangle\in\mathbb{F}_2$$

验证者从所有保留下来的步骤重建系数，形成线性系统：

$$A_{\mathcal I}m=y_{\mathcal I}$$

只要系数矩阵秩达到 `L`，便可通过 GF(2) 高斯消元唯一恢复载荷。对近似随机的系数，当收到 `r` 个方程且 `r>=L` 时，论文使用的满秩概率下界为：

$$\Pr[rank(A_{\mathcal I})=L\mid R=r]\ge1-2^{-(r-L)}$$

这解释了额外方程数的作用：若比载荷长度多收 8 个独立方程，失败概率上界约为 `2^-8`；步骤擦除只会减少方程数量，不会导致固定码块整体失效。

### 3.10 检测、身份恢复与误报

AgentMark 不是用单个 z 分数判断绿色行为是否过多，而是检查线性系统能否一致地解释为某个载荷。若收到 `L+k` 个方程，额外的 `k` 个约束会压低随机日志或错误密钥偶然通过的概率。实验观察到误报随 `k` 近似按 `2^-k` 下降。

需要区分两个条件：

- **满秩**保证候选载荷唯一。
- **一致性**用于拒绝随机日志与错误密钥。

只有方程数刚好等于载荷长度时，随机满秩系统通常总能解出某个载荷，因此额外校验方程对低 FPR 至关重要。

### 3.11 分布保持证明的边界

差分重组严格保持给定 `P_t` 的单步边际分布。如果 `P_t` 是环境历史的条件分布，且每一步都被精确保持，那么依据链式法则，整体轨迹分布也应保持。然而工程系统中的 `P_t` 是通过额外提示诱导的近似，而非模型原生策略；量化、概率解析、候选集合截断和上下文差异都会引入误差。因此论文的理论保证应理解为“采样器不会进一步改变显式分布”，而不是“完整黑盒智能体与原始系统绝对不可区分”。

## 4. 与相关方法的比较

| 方法 | 水印载体 | 是否改变行为边际 | 载荷 | 缺失日志处理 | 主要限制 |
|---|---|---:|---:|---|---|
| Agent Guide / RG | 绿色行为命中频率 | 是 | 零比特存在性 | 依靠长序列统计 | 长轨迹可能累积策略漂移 |
| LLM token 水印 | 输出 token | 依方法而定 | 零比特或多比特 | 面向文本改写 | 无法直接标记规划决策 |
| AgentMark-F | 高层规划行为的采样选择 | 对显式 `P_t` 保持不变 | 多比特 ID | RLNC 支持擦除和截断 | 依赖概率、日志和上下文同步 |
| SynthID-Text + AgentMark | 动作文本 + 规划行为 | 两层独立处理 | 内容存在性 + 行为 ID | 分别抵抗文本改写与轨迹擦除 | 系统复杂度和验证数据需求更高 |

相较 Agent Guide，AgentMark 有四项实质升级：从概率偏置改为分布保持采样；从存在性统计扩展为多比特标识；从依赖完整轨迹扩展为 RLNC 擦除恢复；从单一社交模拟扩展到 ALFWorld、ToolBench 和 OASIS。

## 5. 实验设置与结果解读

### 5.1 实验环境

| 环境 | 任务性质 | 主要用途 |
|---|---|---|
| ALFWorld ID/OOD | 文本具身家庭任务，六类长程规划任务 | 测试长轨迹效用、跨分布泛化和容量 |
| ToolBench | 单工具与多工具调用，共六个子集 | 测试真实 API 规划与短轨迹容量 |
| OASIS | Twitter-like 与 Reddit-like 多智能体社交模拟 | 测试开放式社交质量与水印可验证性 |

主要黑盒模型为 DeepSeek-Chat；附录使用 Gemini 2.0 Flash 做跨模型验证；与 SynthID-Text 的兼容实验使用 Llama-3.2-3B-Instruct。

### 5.2 对比方法

- **Base**：使用相同的显式概率诱导接口，但不嵌入水印。
- **RG**：Agent Guide 风格的红绿行为水印，绿色比例 0.5，logit 偏置 2.0。
- **AgentMark-F**：差分重组、CyclicShift 和 RLNC 组成的完整方法。

Base 与 Ours 共用概率诱导接口，因此能隔离水印采样器本身的影响。附录另设无概率诱导的标准 ReAct，用来检查诱导接口是否改变任务表现。

### 5.3 效用与容量

| 设置 | Base 成功率 | RG 成功率 | AgentMark-F 成功率 | AgentMark-F 容量 |
|---|---:|---:|---:|---:|
| ALFWorld ID | 89.5% | 78.8% | 89.3% | 1.19 bit/step，25.5 bit/task |
| ALFWorld OOD | 96.8% | 94.5% | 97.5% | 1.34 bit/step，28.4 bit/task |
| ToolBench | 59.9% | 58.5% | 59.7% | 0.49 bit/step，4.93 bit/task |

最关键的结果出现在 ALFWorld ID：RG 使平均成功率下降 10.7 个百分点，并把平均轨迹从 19.7 步拉长到 26.1 步；AgentMark-F 相对 Base 只下降 0.2 个百分点，轨迹长度反而从 19.7 变为 19.4。它直接支撑了论文的主张：行为概率偏置会损害长程任务，而分布保持采样能避免这类系统性漂移。

不过各子任务的单次差异并不都接近零，例如 ALFWorld-ID A5 从 94.4% 变为 88.9%。作者强调的是跨任务平均趋势而不是逐项严格等价，结果方差也很大。更严谨的效用等价结论仍需要配对统计检验或预注册的等价区间。

### 5.4 概率诱导是否本身改变策略

附录将无诱导 ReAct、诱导后无水印 Base 和 AgentMark-F 比较：

| 场景 | 无诱导 ReAct | AgentMark-F | 诱导 Base |
|---|---:|---:|---:|
| ALFWorld ID | 83.1% | 89.3% | 89.5% |
| ALFWorld OOD | 94.5% | 97.5% | 96.8% |
| ToolBench | 59.6% | 59.7% | 59.9% |

诱导接口没有造成成功率下降，甚至在 ALFWorld ID 上表现更高。作者认为结构化候选概率提示促进了规划。但这也说明显式 `P_t` 不完全等价于原始隐式策略：即使最终效用未下降，行为分布本身可能已经改变。

### 5.5 跨模型结果

Gemini 2.0 Flash 上，AgentMark-F 与对应 Base 的成功率仍接近：ALFWorld ID 为 67.8% 对 70.6%，OOD 为 72.8% 对 71.7%，ToolBench 为 75.8% 对 75.6%。说明分布保持采样机制不依赖 DeepSeek-Chat，但只覆盖两种 API 模型，还不能代表所有智能体框架。

### 5.6 社交模拟

OASIS 的 Twitter-like 和 Reddit-like 平台各收集 100 条轨迹，其中有水印与无水印各 50 条。每次运行包含 10 个智能体和 10 个环境步骤，作者用 LLM judge 评价连贯性、记忆准确性、角色稳定性、社会规范与语言多样性。图 3 显示 AgentMark-F 保持了社交质量并维持较高可验证性，但正文没有像 ALFWorld 表格一样给出所有原始数值，且 LLM judge 评价仍可能受到模型偏差影响。

### 5.7 误报与错误密钥

作者基于 281 条 ToolBench 轨迹和 159 个不同动作索引构造系数矩阵，对 128-bit 载荷进行每个设置 1000 次蒙特卡洛试验：

| 额外方程 `k` | 无水印日志 FPR | 错误密钥 FPR |
|---:|---:|---:|
| 0 | 60.60% | 60.60% |
| 2 | 22.70% | 23.30% |
| 4 | 7.00% | 5.90% |
| 6 | 1.10% | 1.20% |
| 8 | 0.40% | 0.50% |
| 14 及以上 | 0/1000 | 0/1000 |

这组结果说明“可解出某个 ID”不能直接作为验证标准，必须收集超过载荷长度的额外方程。`0/1000` 只表示此次仿真未观察到误报，并不等于真实概率为零。

### 5.8 步骤擦除与截断

论文用 ToolBench 日志测试 8-bit ID，将每个步骤以概率 `p` 独立删除，并比较 RLNC 与无索引重复码。RLNC 在单轨迹和跨轨迹全局聚合下都更耐擦除，全局聚合因为能累积更多独立方程而出现更晚的解码崩溃点。

需要注意，作者只选择了无攻击时能够 100% 解码的长轨迹：RLNC 使用 25 条，重复码使用 19 条。因此图 5 描述的是“已有足够初始容量的轨迹在擦除后的条件鲁棒性”，不代表全部 ToolBench 短任务都能单独恢复 8-bit ID。ToolBench 平均容量只有 4.93 bit/task，本身就说明许多任务必须跨轨迹聚合。

### 5.9 语义重写

在 ALFWorld-OOD 的 134 个任务、2326 个步骤上，作者只改写当前观察的措辞并保持原始历史不变：

| 条件 | 行为匹配率 | 平均 KL | 比特恢复率 |
|---|---:|---:|---:|
| 无改写 | 100% | 0 | 100% |
| 语义重写 | 49.45% ± 16.90% | 3.227 ± 1.802 | 16.84% ± 19.56% |

这个实验实际上暴露了 AgentMark 的主要弱点：语义等价的表面改写就会使哈希上下文和显式概率发生明显变化，单步比特恢复只剩 16.84%。作者认为长轨迹和短 ID 可以通过聚合补偿，但论文没有在该重写条件下直接报告最终 ID 的端到端恢复率。因此，“对语义重写鲁棒”应谨慎理解为仍残留部分可聚合信号，而不是单步同步稳定。

### 5.10 与 SynthID-Text 兼容

在 149 条 ToolBench 轨迹上同时启用 AgentMark-F 和 SynthID-Text 后，行为水印解码保持 100%，SynthID-Text 检测率为 96.64% ± 0.06%。这验证了规划层和动作文本层能够同时承载不同水印，但没有测试二者同时遭受轨迹擦除与文本改写的联合攻击。

## 6. 可学习与可应用的思想

### 6.1 从“改变概率”转向“利用随机性编码”

AgentMark 最值得借鉴的思想是：若系统本身包含随机选择，不一定要通过分布偏移产生水印。可以把原分布分解成容易编码的均匀子信道，再用密钥重排候选索引，使信息存在于选择与密钥的对应关系中，而外部观察到的边际分布不变。

### 6.2 变容量信道与无喷泉式编码结合

智能体每一步的候选数量和熵都不同，固定每步一位会浪费高熵步骤，也会在低熵步骤强行改变决策。CyclicShift 根据桶大小自适应嵌入 0 到多位，RLNC 再把这些不定长位置变成可任意聚合的线性方程。这种“局部自适应容量 + 全局无固定码块恢复”的设计可迁移到工具调用、路由选择、多轮对话策略甚至多模型协作。

### 6.3 对语音智能体的启发

在语音 Agent 中，行为层可以是是否澄清、调用哪种工具、选择哪种响应策略或切换何种合成风格，而动作层是具体文本和语音。AgentMark 可与音频波形水印并行：行为水印提供跨轮次的系统级身份，音频水印提供单段媒体级溯源。但上下文哈希必须使用稳定的语义状态 ID，而不能直接哈希易受 ASR 错误和同义改写影响的原始文本。

### 6.4 可进一步改进的方向

- 用结构化环境状态、工具调用 ID 和稳定事件标识符派生随机数，降低文本改写造成的失步。
- 将候选行为集合与概率一起签名，防止验证日志中的 `P_t` 被篡改。
- 对显式概率进行校准，并直接衡量其与原始采样策略的总变差距离。
- 引入同步码或局部锚点，支持步骤插入、重排和主动上下文编辑。
- 在固定 FPR 下报告完整 ID 的恢复率，而不仅是单步 bit recovery 或线性系统一致性。
- 与喷泉码、Reed–Solomon、带索引重复码和其他分布保持多比特水印做更公平比较。

## 7. 一句话总结

**AgentMark 将智能体的非均匀规划分布差分重组为均匀子信道，在不改变显式行为边际分布的情况下通过密钥循环移位写入多比特 ID，并利用 RLNC 从残缺轨迹恢复身份，是 Agent Guide 从“可检测偏置”升级为“效用保持、多比特、可擦除恢复”行为水印的完整版本。**

## 9. 复现难度

### 9.1 难度判断

**中高。** 数学模块可以独立实现，但端到端复现需要黑盒 LLM API、三个智能体环境、稳定的概率诱导 prompt、上下文规范化、RLNC 和多种评测脚本。官方仓库提供 Docker、仪表盘与实验目录，降低了工程门槛，但 ToolBench 数据和 API 成本仍不可忽略。

### 9.2 最小算法复现

1. 构造一个有限行为列表和非均匀概率分布。
2. 按固定精度量化并稳定排序。
3. 计算 `d_k`、`T_k`、`q_k`，验证所有 `q_k` 之和为 1。
4. 用大量样本验证最终行为频率与输入 `P_t` 一致。
5. 实现 CyclicShift 编解码，覆盖桶大小 1、2 的幂以及非 2 的幂。
6. 用稳定序列化后的结构化上下文派生局部密钥。
7. 实现 GF(2) RLNC 与高斯消元，验证随机擦除后的满秩恢复。
8. 分别测试正确密钥、错误密钥、随机日志、上下文改写和行为替换。

### 9.3 完整实验复现关键项

| 项目 | 注意事项 |
|---|---|
| Python | 官方 README 要求 Python 3.9+；OASIS 子环境建议 Python 3.10+ |
| 环境 | ALFWorld、ToolBench、OASIS Twitter/Reddit |
| 模型 | DeepSeek-Chat；附录 Gemini 2.0 Flash；兼容实验 Llama-3.2-3B-Instruct |
| 代码结构 | `agentmark/core` 为编码核心，`experiments` 下分别包含三类环境与鲁棒性测试 |
| 随机性 | 概率量化精度、稳定排序、上下文序列化和 PRG 必须在编码端与验证端完全一致 |
| 日志 | 至少记录行为标签、完整候选概率、步骤上下文和轨迹归属 |
| ToolBench | 需要额外下载官方数据和检索缓存，数据规模约数 GB |
| 评测 | 同时报告成功率、步数、bit/step、bit/task、端到端 ID 恢复率和固定 FPR |

### 9.4 最容易复现失败的地方

- 概率相同但排序规则不同，导致桶内容错位。
- 浮点精度、JSON 字段顺序或空格差异改变上下文哈希。
- 编码端与验证端对候选行为名称使用不同规范化形式。
- 丢失步骤后仍使用顺序载荷指针，而不是独立的 RLNC 方程。
- 把后续动作文本当作规划行为验证，混淆行为层与动作层。
- 只检查方程可解而不添加额外一致性方程，造成很高误报。

## 10. 300–500 字总结

AgentMark 是面向黑盒 LLM 智能体的多比特行为水印框架，目标是在不损害任务效用的前提下，把所有者标识嵌入工具选择、子目标选择等高层规划轨迹。方法先提示智能体显式输出有限候选行为的概率分布，再按概率降序做差分切片，将任意非均匀分布分解为若干“前 k 个行为上的均匀桶”。编码器用共享密钥和步骤上下文派生随机数选择桶，并通过 CyclicShift 把变长载荷映射为桶内行为索引。由于先选桶再桶内均匀采样后的边际概率严格还原原分布，水印不会像红绿偏置那样持续推动策略漂移。为抵抗日志丢失和轨迹截断，论文把身份位编码为 GF(2) 上的随机线性方程；验证者只要从残余步骤收集到满秩方程组即可恢复 ID。实验覆盖 ALFWorld、ToolBench 和 OASIS：AgentMark-F 在 ALFWorld-ID 上将成功率保持在 89.3%，而偏置式 RG 从 89.5% 降至 78.8%；容量约为 ALFWorld 1.19–1.34 bit/step、ToolBench 0.49 bit/step。其主要局限是保证只针对诱导得到的显式分布，验证依赖概率日志和严格上下文同步；语义改写后单步比特恢复率仅 16.84%，完整自适应攻击也未验证。因此它在算法结构和效用证据上明显强于 Agent Guide，但真实部署仍需解决稳定上下文、日志可信性和主动篡改问题。

## 11. 论文写作逻辑

论文的论证结构较完整：

1. 先区分规划行为和执行动作，说明内容水印无法覆盖前者。
2. 以 Agent Guide 式概率偏置为反例，指出长轨迹中的分布漂移会累积成效用损失。
3. 将问题抽象为时变离散信道，明确提出单步分布保持与缺失日志下可解码两个目标。
4. 先给通用 AgentMark 框架，再给 AgentMark-F 的具体实例：差分重组负责分布分解，CyclicShift 负责近最优变长编码，RLNC 负责跨步骤恢复。
5. 用 ALFWorld 的长程任务证明 RG 的效用损失，用 ToolBench 和 OASIS 扩展到工具与社交场景。
6. 分别验证错误密钥、日志擦除、语义重写和内容水印兼容性。
7. 在附录补充分布保持证明、端到端样例、容量界、跨模型实验和复现细节。

其优点是动机、理论设计和主实验高度对应：每个模块都解决一个明确问题。相对薄弱之处是“行为分布显式诱导近似真实策略”的核心假设主要通过任务成功率间接验证；语义重写实验暴露明显同步下降后，论文又以聚合可能恢复进行解释，却没有给出改写攻击下的最终 ID 恢复曲线。

# AuxMark：利用辅助行为水印防御未授权 Agent 蒸馏

> **论文：** AuxMark: Defending Against Unauthorized Agent Distillation via Auxiliary Behavioral Watermarking  
> **作者：** Yiqing Feng, Haozhe Feng, Shunan Shang, Xiaoyu Zhang, Jian Lou, Haodong Zhao, Mingxun Zhou  
> **来源：** arXiv:2609.34597 [cs.CR]，2026（预印本）  
> **链接：** [Paper](https://arxiv.org/abs/2609.34597) | [PDF](https://arxiv.org/pdf/2609.34597) | [Code](https://github.com/qx041609/Auxmark) | [Models](https://huggingface.co/AuxMark/AuxMark/tree/main)  
> **代码：** 已开源，仓库包含嵌入、蒸馏、探针生成、检测、轨迹排序和三类 benchmark adapter。

## 0. 摘要

AuxMark 面向一种与 Agent 重包装不同的侵权方式：攻击者批量查询教师 Agent，收集包含思考、工具调用和观察反馈的完整多步轨迹，再用这些轨迹微调学生模型。此时，水印必须能够被学生模型学进去，并在只有黑盒查询权限时被检测出来。

方法在教师轨迹的正常核心动作后动态插入安全、非必要但上下文合理的辅助工具动作，同时把触发该动作的上下文保存为私有 evidence card。审计可疑学生时，系统从每张卡构造一对探针：real probe 保留真实核心动作与辅助动作之间的依赖，fake probe 用语义相近但不同的核心动作替换它。只有学生真正从水印轨迹学到了特定依赖，real 的完整命中率才应显著高于 fake。论文以 evidence card 为统计单位进行单侧精确符号检验，并增加最小效应差阈值。

实验覆盖 BFCL、SWE-bench、Telecom 三个 benchmark，两种教师 Agent 和四种学生架构。24 个蒸馏学生全部被检出，48 个干净模型均未误报；在 10 倍干净数据稀释、轨迹改写、截断和自适应清洗下仍保持显著。教师准确率变化位于 -3% 到 +3%，平均交互步数从 20.49 增至 21.09。

## 1. 研究背景与核心问题

Agent 轨迹比普通问答文本包含更丰富的监督：它记录何时调用什么工具、怎样传参、如何依据观察继续行动，因此非常适合蒸馏。传统 token 水印可能在微调时被弱化；基于固定动作或固定转移模式的 Agent 水印又容易跨任务失效。

AuxMark 的核心思想不是给每条输出编码固定 bit，而是有意识地制造可学习的“核心动作 → 辅助动作”条件习惯。学生若在这些轨迹上训练，就可能复现该依赖。验证时再通过真实/伪造上下文对照，区分“学生记住了水印关系”与“模型本来就喜欢调用这个工具”。

## 2. 威胁模型与前提

模型所有者完全控制在线教师 Agent，可以实时改写其轨迹并私下保存证据。攻击者只有黑盒接口，但会系统性抓取完整多步轨迹并用于微调学生。所有者之后只能黑盒访问可疑学生，但可以自由构造输入。

一个重要前提是所有者先通过查询风格、IP、请求频率等服务器侧信号得到可疑轨迹集合。论文承认集合中并非所有轨迹都实际进入蒸馏训练，因此实验采用 100 条可疑轨迹、其中 50 条真实训练轨迹的 50% precision 设置。AuxMark 解决的是“在已有可疑集合后如何提供行为证据”，并不独立解决谁在抓取数据。

## 3. 方法设计与复现级理解

### 3.1 阶段一：离线筛选安全工具

系统首先让安全模型读取当前工具 schema，只允许只读、不会修改环境状态或改变任务进程的工具进入安全集合。该判断预先执行并缓存，避免每一步都调用安全模型。这个约束是“harmlessness”的基础：辅助动作可以增加观察与步数，但理论上不应改变外部状态。

### 3.2 阶段二：动态决定何时注入

每条轨迹维护当前注入概率和剩余预算。在第 `t` 个核心动作完成后，系统使用密钥、账户、轨迹 ID 和步号生成伪随机数：

$$u_t=H(k\Vert a\Vert id_{\tau}\Vert t)\in[0,1)$$

仅当预算仍大于 0 且随机值低于当前概率时才尝试生成辅助动作。若成功注入，概率回到基础值并消耗一次预算；若生成失败或本轮不满足条件，概率逐步升高直到上限。这样既限制每条轨迹的额外动作数，又避免固定间隔形成明显模式。

### 3.3 阶段三：生成并选择辅助动作

候选生成器根据历史、刚完成的核心动作及其观察，提出若干辅助 thought/action。候选必须使用安全工具，参数必须能从已有上下文中合理推出。评分器综合三项：与上下文的相关性、动作可靠性，以及同一核心工具—辅助工具配对过去成功注入的次数。

$$S_j=\alpha s_{rel}^j+\beta s_{relb}^j+\gamma s_{rep}^j$$

重复性分数不是单纯追求多样，而是鼓励稳定的条件行为，使有限蒸馏数据更容易让学生学到该模式。最高分候选被执行并加入公开轨迹。

### 3.4 阶段四：保存私有 evidence card

每次成功插入都会保存一张证据卡，内容包括此前历史、前置核心 thought/action、核心观察，以及辅助工具和参数：

$$c_t=(h,t_{core}^{t-1},a_{core}^{t-1},o_{core}^{t-1},f_{aux},p_{aux})$$

证据卡不随轨迹公开。审计时，所有者从可疑轨迹集合取出对应卡片，合并成验证池。私有卡既是后续构造探针的依据，也是攻击者难以准确知道哪些依赖会被审计的秘密信息。

### 3.5 阶段五：构造 real/fake 成对探针

对每张卡，real probe 保留原核心机制，并修改一个参数生成多个逻辑一致的变体，同时更新期望辅助参数。fake probe 则把核心动作替换为语义相近但机制不同的动作，同时仍要求相同辅助目标。如果学生只是在一般语境下偏爱该辅助工具，real 和 fake 都可能命中；如果学生学到了原水印轨迹中的特定条件依赖，real 应显著高于 fake。

输出评估分两级：tool hit 只要求工具名匹配，full hit 还要求参数结构和值完全一致。论文最终以更严格的 full hit 作为主检测信号。

### 3.6 阶段六：卡片级符号检验

同一卡片派生的多个参数变体并不独立，因此论文先对卡片内部求 real 与 fake 的平均 full-hit，再计算差值：

$$\Delta_i=R_i^{real}-R_i^{fake}$$

去掉平局卡片后，令 `w` 为 real 胜出的卡片数，`l` 为 fake 胜出的卡片数，执行单侧精确符号检验。检测必须同时满足显著性和效应大小两道门槛：`p < 0.05`，且所有卡片的平均差值至少为 0.05。后一个条件防止样本量很大时把极小但无实际意义的差异判为水印。

### 3.7 轨迹级归因

模型级检测只能判断学生是否蒸馏自这批轨迹。若要进一步定位哪几条可疑轨迹真正用于训练，论文对每条轨迹的 real/fake full hit 与 tool-only hit 做分位数归一化，再计算排序分数：

$$S_{\tau}=Q(R_{\tau}^{real})-\alpha'Q(R_{\tau}^{fake})+\beta'Q(T_{\tau}^{real})-\gamma'Q(T_{\tau}^{fake})$$

real 命中提供主要正证据，fake 命中被惩罚，tool-only 命中作为部分记忆的辅助信号。最终以 Top-K 轨迹作为最可能的训练来源。

## 4. 统计设计为何合理

如果把同一 evidence card 的多个改参版本当作独立样本，会人为扩大样本量并得到过小的 p-value。AuxMark 在卡片内聚合，再以卡片为独立单位做符号检验，避免这种伪重复。real/fake 配对也比单独统计目标动作出现率更可靠，因为它控制了模型固有工具偏好、提示模板与一般任务语义。

不过，符号检验只利用差值正负而忽略差值大小，统计功效可能偏低；论文用额外的平均差值阈值补充实际效应，但该阈值来自经验设置。卡片之间若共享高度相似的上下文或工具配对，独立性仍可能弱于假设。

## 5. 实验设置

| 维度 | 设置 |
|---|---|
| Benchmark | BFCL、SWE-bench、Telecom（Tau2） |
| 教师 Agent | GPT-OSS-120B、Kimi-K2.5 |
| 候选评分/安全模型 | Qwen3-8B |
| 学生模型 | Mistral-24B、GLM-4.7-Flash、Qwen3-14B、Qwen3-32B |
| 蒸馏方式 | 对 thoughts 与 actions 监督，LoRA rank 32、alpha 64、学习率 `2e-4` |
| 可疑集合 | 100 条轨迹，其中 50 条实际进入训练 |
| 检测门槛 | 单侧 card-level sign test `p < 0.05`，平均 full-hit gap 至少 0.05 |
| 对比方法 | AgentWM、SeqWM |
| 攻击 | 1×/5×/10× 干净数据稀释、改写、截断、进阶混合、自适应辅助动作清洗 |
| 无害性 | 4 个教师/数据组合，共 200 个任务 |

开源仓库给出的默认训练配置为 BF16、20 epochs、batch size 1、gradient accumulation 2，并提供 BFCL、SWE-bench 与 Tau2 adapter、探针回放和结果文件。

## 6. 主要实验结果

### 6.1 蒸馏模型检测

三类 benchmark、两种教师和四种学生的 24 个组合全部达到显著检测。以 BFCL 为例，GPT-OSS-120B 教师下 real full-hit 为 24.2%–59.3%，fake 为 15.4%–44.0%；Kimi-K2.5 下 real 为 21.6%–46.2%，fake 为 4.7%–27.7%，所有组合均通过双门槛。

48 个干净模型组合均未被判为水印模型。这里的“零误报”是有限样本上的 0/48，不代表真实世界 FPR 被理论证明为 0。

### 6.2 与基线比较

在匹配蒸馏设置中，AgentWM 只有 GLM-4.7-Flash 在 BFCL 和 SWE-bench 上达到论文设定的通过标准，其余学生失败；SeqWM 所有中位 p-value 均大于 0.05。AuxMark 的优势来自让学生学习上下文依赖，而不是要求原始轨迹中某个固定全局模式在不同架构微调后仍直接保留。

### 6.3 对教师效用的影响

四个 BFCL/Telecom 教师组合中，准确率差在 -3% 到 +3% 之间，没有一致下降趋势。平均交互步数从 20.49 增至 21.09，各组合变化为 -1.38 到 +2.04 步。辅助动作虽然只读，但仍可能改变后续可见观察和上下文长度，因此“安全工具”不等于完全零干扰；论文给出的是经验无害性。

### 6.4 对数据处理攻击的鲁棒性

- 干净数据按水印数据的 1×、5×、10× 混入时，24 个设置全部被检出；最强 1:10 稀释下的 8 个学生也全部显著。
- DeepSeek-V4-Flash 改写训练轨迹后，BFCL 与 Telecom 共 8 个设置全部显著。
- 攻击者知道水印依赖辅助行为，并用 DeepSeek-V4-Flash 删除疑似辅助动作后，8 个学生仍全部被检出，最弱 p-value 为 `9.6e-3`。
- 当可疑集合中真实训练轨迹比例降至 20% 时，24 个设置全部保持显著；降至 10% 时仍有 21/24 显著。

## 7. 消融与工程观察

- 注入概率、概率增量、最大概率与总预算共同控制证据卡数量和交互开销；开源命令示例使用基础概率 0.1、增量 0.1、上限 1.0、预算 10。
- 重复性奖励会让学生更容易学到一致行为，但也可能使工具配对在数据中更显眼，形成可被频率分析发现的模式。
- full hit 比 tool hit 更严格、证据更强，但对参数序列化和微小格式差异敏感；实际服务需要稳定的结构化 tool-call 解析。
- 轨迹归因是候选集合内的排名问题。Precision@K 需要离线知道哪些轨迹进入训练，部署时只能输出相对嫌疑顺序。

## 8. 论文的主要贡献

1. 将 Agent 水印目标从“证明某条输出来自教师”转向“证明学生从带水印轨迹中蒸馏过”。
2. 设计安全辅助动作，使水印成为学生可学习的条件行为，而不是脆弱的表面文本模式。
3. 用私有 evidence card 保存精确上下文，使后续黑盒验证无需访问学生参数。
4. 通过 real/fake 成对探针控制模型固有偏好，并在卡片层面处理统计依赖。
5. 同时提供模型级检测与轨迹级来源排序，并公开了较完整的端到端代码和结果材料。

## 9. 局限性与批判性分析

第一，方法依赖服务器先识别可疑抓取流量。如果攻击者低频、分布式或模仿正常用户采集，所有者可能无法把真实训练轨迹纳入证据池。实验中的 50% precision 是给定条件，不是 AuxMark 自身产生的检测能力。

第二，水印通过额外工具调用进入公开轨迹。即使单个动作合理，攻击者仍可用频率、因果必要性或轨迹压缩模型识别“对完成任务没有贡献”的步骤。论文的自适应清洗只使用一种清洗模型和一种提示策略，不能代表充分自适应攻击。

第三，学生必须对具体核心—辅助依赖发生可测记忆。更强的数据去重、只保留成功路径、只蒸馏最终 action、参数归一化、强化学习而非监督微调，均可能降低该依赖的传递率。

第四，fake probe 的质量是检测可信度的核心。若替换后的核心动作并非真正语义等价，real/fake 差异可能来自任务难度或上下文自然度，而不完全是水印记忆。论文借助教师生成变体，但没有给出形式化等价保证。

第五，“24/24 检出、0/48 误报”覆盖范围仍有限。教师只有两种，安全/评分器固定为 Qwen3-8B，学生规模和蒸馏算法也有限，真实商业闭源 Agent 的采样策略与工具接口可能明显不同。

## 10. 复现建议

1. 直接使用官方仓库的三类 adapter 和已发布 probes/results，先复算 card-level 检验，再运行新的模型调用。
2. 严格保护 secret seed、安全策略和 evidence cards；公开这些材料会让攻击者获得清洗与规避目标。
3. 以卡片为统计单位，不能把同一卡片的多个参数变体直接当作独立样本。
4. 固定 tool-call 的结构化解析与参数规范化，分别报告 tool hit、full hit、real/fake gap、非平局卡片数和 p-value。
5. 无害性除准确率和步数外，还应补充 token、时延、工具费用、异常率及观察污染。
6. 攻击扩展应包括仅蒸馏 actions、去除 thoughts、轨迹最短化、多模型投票清洗、跨教师混合、DPO/RL 蒸馏及低频分布式采集。

## 11. 对后续研究的启发

AuxMark 的核心价值是把水印视为一种“可迁移的行为习惯”，这比单纯在输出中放置静态标记更适合蒸馏场景。类似思想也可用于语音 Agent：在不改变任务结果的前提下嵌入上下文相关的工具选择、确认策略或声学辅助行为，再用成对反事实查询验证学生是否学到了特定依赖。不过，任何辅助行为水印都必须同时优化可学习性、任务无害性和抗清洗隐蔽性，三者存在天然张力。

## 12. 一句话总结

AuxMark 通过“安全辅助动作 + 私有证据卡 + real/fake 成对探针 + 卡片级统计”把 Agent 轨迹水印转化为黑盒反蒸馏证据，实验与开源复现材料较完整，但其有效性仍依赖可疑流量识别和辅助行为未被强力清洗。

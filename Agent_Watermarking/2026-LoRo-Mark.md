# LoRo-Mark：可证明无损且稳健的 Agent 水印

> **论文：** LoRo-Mark: Provably Lossless And Robust Agent Watermarking  
> **作者：** Haoyang Zou, Yao Wang, Jun Yao, Weiming Zhang, Han Fang  
> **来源：** arXiv:2609.34080 [cs.CR]，2026（预印本）  
> **链接：** [Paper](https://arxiv.org/abs/2609.34080) | [PDF](https://arxiv.org/pdf/2609.34080)  
> **代码：** 论文称补充材料包含实现代码与复现说明，但截至本文整理时未给出可核实的独立公开仓库链接。

## 0. 摘要

LoRo-Mark 面向 Agent repackaging：攻击者通过 API 调用受保护 Agent，把其编排逻辑和工具策略包装成自己的服务，并可能修改部分执行轨迹以掩盖来源。论文认为现有行为水印会干预正常决策，所以即使平均性能下降很小，也难以严格声称“无损”。

LoRo-Mark 的解法是把水印完全隔离到一个经过 MAC 鉴权的取证分支。普通用户请求沿原始路径执行；只有所有者构造的合法取证任务才会激活特殊分支。于是，未持有密钥的攻击者让水印分支误触发的概率可归约到 MAC 伪造概率，论文据此给出计算意义上的无损保证。进入取证分支后，系统把版权消息重复编码，并通过密钥置换将比特分散到多步候选行为选择中，以抵抗行为替换和轨迹截断。

实验基于 xLAM-function-calling-60k，覆盖三种 LLM backbone。10,000 个正常请求中误激活为 0；Data、Business、Social 三个域的四项任务指标与无水印 Agent 完全相同。默认重复因子为 3 时，保留约 34.6% 的前缀步骤即可达到 100% TPR；提高重复因子能增强替换鲁棒性，但会把取证序列拉长到 52–122 步。

## 1. 研究背景与核心问题

传统 Agent 水印通常在正常轨迹中偏置工具选择、执行路径或动作分布。这样做的问题不只是可能降低准确率，还在于“实验上没有明显下降”不等同于“任何普通请求都不受影响”。LoRo-Mark 把目标提高到两个层面：

- **无损性：** 对不知道密钥的普通调用者，受保护 API 与原始 API 在计算上不可区分；
- **稳健性：** 所有者从黑盒重包装服务触发取证执行后，即使部分行为被替换或后缀被截断，仍能恢复版权消息。

论文的关键转折是：不再要求水印存在于每次正常服务行为中，而是让水印只存在于所有者可认证触发的特殊取证执行中。

## 2. 威胁模型与“无损”的准确含义

攻击者能黑盒调用目标 Agent，将其接入自己的应用并改变部分行为或截断执行序列。所有者只能访问重包装后的外部接口，不能查看其内部模型与编排代码。系统假设保护层、主密钥和分支逻辑仍被攻击者实际使用，并假设 MAC 与 PRF 安全。

这里的“provably lossless”不是说取证请求也与原 Agent 行为完全一致，而是说**所有未成功伪造认证标签的请求均走原始路径**。因此证明对象是未授权普通查询的 API 分布，而不是水印分支自身的隐蔽性、成本或任务质量。

## 3. 方法设计与复现级理解

### 3.1 第一阶段：密钥派生与取证任务生成

系统从 master key 通过域分离 PRF 派生三个子密钥：检测密钥用于 MAC，嵌入密钥用于把标签编码进合法任务参数，证明密钥用于控制取证行为序列。所有者选择合法任务正文，计算截断 MAC，再把标签编码到任务已有参数中，形成取证任务。

$$\sigma=\mathrm{MAC}_{\ell}(k_{det},T_{body})$$

$$P=E(T_{body},\sigma,k_{emb})$$

$$T^*=T_{body}\oplus P$$

这里的符号 `oplus` 表示把参数组件组合进任务，不应理解为逐比特异或。关键要求是参数仍满足任务语法与容量约束，使认证信息不会以额外外部字段直接暴露。

### 3.2 第二阶段：在线检测与分支隔离

服务收到任务后，从参数解码标签，并独立重算正文的 MAC。二者相同才进入取证分支，否则不调用任何水印逻辑，直接运行原始 Agent。

$$\sigma_{expected}=\mathrm{MAC}_{\ell}(k_{det},T_{body})$$

$$\sigma_{decoded}=D(P,k_{emb})$$

未经授权的任务要进入取证分支，就必须为此前未认证的任务正文构造有效 MAC。因此误触发概率受 MAC 的 EUF-CMA 安全性约束。

### 3.3 第三阶段：重复编码版权消息

将版权字符串转为 `n` 个比特后，论文不是连续重复每个 bit，而是把整个消息复制 `r` 次再串接。这样同一 bit 的各副本在序列中相距较远，后缀截断不会立即删掉某个 bit 的全部副本。

$$M=(c_0c_1\cdots c_{n-1})\Vert\cdots\Vert(c_0c_1\cdots c_{n-1})$$

每个取证请求根据其认证标签派生独立步级密钥：

$$k_{step}=\mathrm{MAC}(k_{prv},\sigma)$$

### 3.4 第四阶段：把比特映射到候选行为

在第 `t` 步，Agent harness 构造可复现的执行上下文和候选行为集合。若候选数为 `B_t`，该步最多承载：

$$q_t=\left\lfloor\log_2|B_t|\right\rfloor$$

PRF 根据步级密钥、上下文与候选集合生成确定性置换。系统读取接下来的 `q_t` 个消息比特，将其解释为索引并选择对应候选行为。这样，外部看到的是一系列合法行为，而密钥持有者可重建同一候选集合与置换，把行为索引反解为比特。

### 3.5 第五阶段：黑盒验证

所有者向可疑服务发送合法取证任务，收集实际行为序列。验证器先验证任务标签，再逐步重建候选集合与置换；观察行为不在候选集合中时记为擦除，已有行为则恢复索引比特。最后把 `r` 份消息按位多数解码，并与声明版权消息比较。

对于固定大小的候选集合，理论所需步骤数为：

$$S=\left\lceil\frac{8|c|r}{\left\lfloor\log_2|B|\right\rfloor}\right\rceil$$

## 4. 理论保证

论文把水印 API 与原始 API 的不可区分优势定义为两者在攻击者输出上的概率差。若 MAC 对至多 `q` 次查询、时间 `t` 的攻击者具有伪造优势上界，则 LoRo-Mark 的无损区分优势不超过同一上界：

$$Adv_{loss}(A)\leq\epsilon_{MAC}(\lambda)$$

证明思路很直接：两个 API 只有在攻击者构造出可通过鉴权的未授权任务时才可能走不同路径；若这种事件概率不可忽略，就可以把攻击者转化为 MAC 伪造者。

这个定理保证的是普通请求路径完全不被水印逻辑修改，而不是保证取证行为不可识别。论文还分析了取证序列的正确恢复、伪造困难性和重复码在随机替换下的恢复概率，但其鲁棒性依赖候选集合可重建、替换位置近似随机以及足够多步骤被保留。

## 5. 实验设置

| 维度 | 设置 |
|---|---|
| 数据集 | xLAM-function-calling-60k，60,000 条轨迹、3,673 个工具、21 个领域 |
| 效用子集 | Data、Business、Social，每个领域 100 个任务 |
| 默认 Agent | Qwen3-4B + ReAct + function calling |
| 额外 backbone | Qwen3-8B、Ministral-8B-Instruct-2410 |
| 对比方法 | 无水印、AGENTWM、AgentMark、LoRo-Mark |
| 误触发测试 | 10,000 个普通任务 |
| 效用指标 | Pass Rate、Response Score、Trajectory Score、Success Rate |
| 攻击 | 随机行为替换、序列前缀截断 |
| 默认冗余 | `r=3`；消融使用 `r=3,5,7` |
| 固定容量实验 | 候选集合 64，版权消息 13 bytes |

任务效用由 DeepSeek-V3 作为 judge。由于检测与行为嵌入发生在调用 LLM 之前的 harness 中，论文认为方法不依赖具体 backbone。

## 6. 主要实验结果

### 6.1 普通请求无损性

10,000 个正常任务中没有一个误入取证分支，经验 FPR 为 0。Data、Business、Social 三个领域中，LoRo-Mark 的 PR、RS、TS、SR 与无水印 Agent 的对应数值完全相同，所有差值均为 0。这是分支隔离的直接结果，而不是通过训练权重或损失函数权衡得到的近似保持。

### 6.2 行为替换鲁棒性

以 13-byte 消息和 64 个候选行为为例，`r=3,5,7` 分别需要约 52、87、122 步。替换比例为 10% 时，三种设置 TPR 分别为 88%、98.65%、100%；20% 时为 33.60%、73.95%、91.25%；30% 时为 4.70%、27.45%、59.00%。重复因子提高后鲁棒性明显增强，但验证时延和异常长轨迹也同步增加。

### 6.3 截断鲁棒性

默认 `r=3` 时，只保留约 34.6% 的原始前缀即可达到 100% TPR。其原因是整条消息的副本交错分布：一旦前缀覆盖足够多完整或部分副本，多数解码便可以恢复消息。更短前缀则因尚未观察到每个 bit 的充分副本而无法完整恢复。

### 6.4 参数容量与误激活

论文组合测试 14、64、96 bit 参数容量与 32、64、96、128 bit MAC。有效安全强度由两者较小值决定。14-bit 容量时经验 FPR 为 `5.0e-5`，接近理论 `2^-14`；有效位数至少 32 时，10,000 次测试均未出现误激活。由此可见，长 MAC 无法弥补任务参数本身承载空间过小。

## 7. 消融与工程取舍

- 重复因子是最主要的稳健性旋钮：`r` 越大，替换和截断后恢复率越高，但取证轨迹长度线性增长。
- 候选集合越大，单步容量越高；但所有者必须在验证端确定性重建同一集合及顺序，否则会造成系统性解码错误。
- MAC 长度与参数容量共同决定误激活上界，应以二者的最小值评估，而不能只报告密码学标签长度。
- 默认 `r=3` 更像低成本操作点，并不适合强替换攻击；若预期攻击比例达到 20%–30%，实验实际上支持使用更高冗余。

## 8. 论文的主要贡献

1. 将“正常服务质量不受影响”从经验指标提升为基于 MAC 安全性的路径级保证。
2. 把认证触发和版权载荷分开：前者控制谁能进入取证分支，后者负责所有权消息恢复。
3. 通过整消息重复和密钥化候选置换，使行为序列可以携带多 bit 版权信息。
4. 明确展示稳健性与取证长度的量化权衡，而不是只给一个固定超参数结果。

## 9. 局限性与批判性分析

最根本的限制是：LoRo-Mark 的水印不存在于普通用户看到的正常轨迹中，而存在于所有者专门触发的取证分支。因此它证明“被测服务仍响应这一私有协议”，但不直接证明某条普通输出确实来自受保护 Agent，也不保护已发布正常轨迹的完整性。

其次，重包装攻击者若能识别并剥离外围 harness、只转发普通请求，或者针对疑似取证请求做代理分流，水印分支可能根本无法到达。论文的无损证明假设分支逻辑仍在部署路径中，却没有证明攻击者必须保留它。

再次，52–122 步的特殊取证轨迹可能昂贵且易于被服务端限流或行为分析识别。论文强调未授权者难以伪造标签，但“无法伪造触发器”不等于“无法识别触发请求或取证行为”。多次审计后的触发器泄露、密钥轮换与抗重放也未被系统评估。

最后，实验攻击以随机行为替换和简单前缀截断为主。知道候选生成逻辑的攻击者可以针对低容量步骤、候选集合重建条件或重复副本位置进行非随机修改；此时重复码的经验曲线可能过于乐观。

## 10. 复现建议

1. 独立实现三条路径：任务正文规范化、参数标签编码/解码、原始 Agent 调用；确认非触发路径逐字节不经过嵌入逻辑。
2. 使用标准 HMAC 和显式域分离派生三个子密钥，并记录任务参数的真实可用容量。
3. 确保候选集合生成是确定性的，固定工具 schema、排序、上下文序列化和异常行为处理。
4. 除随机替换外，增加定向删高容量步骤、候选重排、拒绝长任务、分支剥离、代理分流和重放攻击。
5. 同时报告取证步数、token、API 调用成本、端到端时延和 TPR，不应只报告普通任务“零下降”。
6. 论文未给出可核实的公开仓库；复现应以正文算法、附录伪代码和实际补充材料版本为准。

## 11. 对后续研究的启发

LoRo-Mark 展示了一种很有价值的设计模式：如果水印干预正常决策必然带来效用争议，可以把所有权协议放在经过认证的旁路中。不过，真正强的系统还需要回答“攻击者为什么不能删除这条旁路”。未来可以把取证分支与不可绕过的模型内部能力、远程证明、可信执行环境或正常行为中的轻量稳健信号结合，形成“正常路径弱证据 + 私有分支强证明”的双层结构。

## 12. 一句话总结

LoRo-Mark 通过 MAC 鉴权的取证旁路实现了严格的普通请求无干预，再用重复编码的行为序列提供黑盒归属证据；理论非常干净，但它保护的是可触发取证能力，而不是每条正常 Agent 轨迹。

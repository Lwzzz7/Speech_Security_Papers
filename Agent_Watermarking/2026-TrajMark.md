# TrajMark：面向编码 Agent 轨迹的所有权归属与分段篡改定位

> **论文：** TrajMark: Ownership Attribution and Segment-Level Tamper Localization for Coding-Agent Trajectories  
> **作者：** Bokang Zeng, Zheng Gao, Xiaoyu Li, Xiaoyan Feng, Jiaojiao Jiang  
> **来源：** arXiv:2609.10416 [cs.CR]，2026（预印本）  
> **链接：** [Paper](https://arxiv.org/abs/2609.10416) | [PDF](https://arxiv.org/pdf/2609.10416)  
> **代码：** 截至本文整理时，论文未给出可核实的官方开源仓库。

## 0. 摘要

TrajMark 研究的不是最终代码补丁是否带有水印，而是编码 Agent 的**可见执行轨迹**是否能够回答两个不同的问题：这批轨迹属于谁，以及轨迹的哪个区段被修改过。论文认为，所有权信号需要在删除、插入和替换后仍能累积，因此应当“稳健”；完整性信号则应当对局部修改敏感，因此应当“脆弱”。用一个全局统计量同时承担两项任务会产生目标冲突。

为此，TrajMark 设计了两个彼此独立的通道。所有权通道在自然出现的 READ 操作上编码 6-bit 部署标识，不新增动作；完整性通道在关键操作区段之间插入 Q12 普通封印、组封印和终止封印，通过密钥化承诺实现协议区段级篡改定位。验证者只需要发布后的可见轨迹、密钥和公开的规范化规则，不需要模型 logits、隐藏思维链、私有运行状态或原始环境。

实验覆盖 SWE-agent、OpenHands、OpenDev 三种编码 Agent、三种 LLM 和三类软件工程任务。干净批次中 27/27 个组合均恢复出正确所有者；穷举单点攻击的检测率为 95.5%–100%；随机单动作破坏中，95.8% 的修改位置被定位到正确的协议区段。完整方案的总体 Pass@1 为 26.9%，无水印对照为 26.3%。

## 1. 研究背景与核心问题

编码 Agent 的输出不仅是最终 patch，还包括检索目录、搜索符号、读取文件、修改代码、运行测试以及提交结果等连续行为。只在最终代码中嵌入水印，无法证明一份公开轨迹确实由某个 Agent 服务产生，也无法发现轨迹发布后是否被局部改写。

已有 Agent 行为水印大多提供全局检测或标识恢复：只要剩余证据足够，整条轨迹仍可能被判定为“有水印”，但验证者不知道哪一段已经不可信。TrajMark 的核心判断是：

- 所有权归属应允许部分载体丢失，强调冗余和批量聚合；
- 篡改定位应在局部内容变化时立即失配，强调局部绑定和脆弱性；
- 因此需要两种载体、两套验证规则和两个独立输出。

## 2. 威胁模型与保护边界

系统由可信嵌入服务、持有同一对称密钥的可信验证者，以及发布后能够编辑轨迹的攻击者组成。攻击者知道算法、声明的标签和公开配置，可以看到其他带水印轨迹，也可以插入、删除或替换可见记录，但不知道密钥，不能控制可信 wrapper，也不能获得自适应的局部告警反馈。

验证对象是轨迹的公开规范投影，包括动作类别、子类型、规范化目标、执行状态、公开 header 和顺序。隐藏推理、logits、完整命令与输出、私有 wrapper 状态以及观察文本均不在保护范围内。换言之，TrajMark 证明的是“公开投影的一致性”，不是完整运行语义的真实性。

论文明确不覆盖 freshness、不可抵赖、任务或会话绑定、整条轨迹重放、同标签替换、跨轨迹拼接、混合标签批次、复合自适应攻击、完全擦除及密钥泄露。对称密钥持有者均能生成有效标记，因此它也不是公共可验证的法律归属证明。

## 3. 方法设计与复现级理解

### 3.1 总体流程：稳健所有权通道与脆弱完整性通道

生成过程中，wrapper 先观察 Agent 原本准备执行的动作。若动作是满足条件的自然 READ，所有权通道可能在保持读取语义和文件目标不变的前提下改写其 READ 子类型。关键动作形成受保护区段后，完整性通道再插入封印动作。发布后，验证器从头重放公开协议：一条路径聚合所有权方程并恢复部署 ID，另一条路径重新计算封印并输出异常区段。

这种分离很关键：所有权通道依靠跨轨迹稀疏累积，即使单条轨迹证据不足也可以在批次上恢复；完整性通道依靠显式、局部链接的承诺，只要受保护投影发生变化，附近封印就应失配。

### 3.2 所有权层：用自然 READ 编码线性方程

部署标识是有限域上的 6-bit 向量。密钥根据规范化文件名决定一个 READ 是否被选为载体，并生成一个非零系数行及掩码。wrapper 选择 Q6 中与方程右端一致的 READ 子类型，但不改变 READ 家族和文件目标。因此 Owner-only 模式不会增加轨迹动作。

验证时，每个 basename 槽位只保留一条聚合方程；重复观察采用多数投票，平票则擦除。验证器穷举 64 个候选标识，计算每个候选满足的方程数。对声明标识的证据分数为：

$$z_{owner}(w_c)=\frac{H(w_c)-U/2}{\sqrt{U/4}}$$

其中 `U` 是保留槽位数，`H` 是被候选标识满足的方程数。只有矩阵秩达到 6、最优候选唯一且证据超过阈值时才作出决定；否则返回 ABSTAIN。论文采用阈值 3.09，对应至少 10 个保留槽位。

### 3.3 完整性层：普通、组与终止三类 Q12 封印

轨迹按关键动作划分为区段。区段投影包含 Q12 READ 子类型计数，以及关键动作的区段内序号、类别和规范化目标。探索性 READ 的顺序、完整命令、观察内容和 OTHER 内容不进入该投影，所以这些字段发生变化并不在论文的完整性声明内。

普通封印对当前区段、区段编号以及前一个普通封印进行 HMAC，并把摘要映射到 12 种可见 READ 子类型之一。组封印把相邻两个普通封印再绑定一次，终止封印负责关闭剩余后缀和整个封印序列。普通封印定位单个区段，组封印定位相邻区段对，终止封印提示后缀或闭合结构异常。

若共有 `m` 个普通封印，额外动作数为：

$$A_{seal}(m)=m+\left\lfloor\frac{m}{2}\right\rfloor+1$$

### 3.4 验证输出为何必须是三态

所有权验证返回 ACCEPT、REJECT 或 ABSTAIN。REJECT 表示证据充分但唯一恢复出的标签不是声明标签；ABSTAIN 表示方程秩、证据量或唯一性不足。这个区分避免把“证据被删光”误说成“证明不属于该所有者”。完整性验证则独立返回 CLEAN 或 ALARM，以及区段、区段对、后缀或结构异常的位置。

## 4. 理论分析

所有权恢复可视为带错误和擦除的线性码解码。令矩阵最小距离为：

$$d(A)=\min_{v\neq 0}\lVert Av\rVert_0$$

若错误向量为 `eta`，满足下面条件即可保证唯一恢复；若另外擦除了 `s` 个槽位，则使用第二个充分条件：

$$2\lVert\eta\rVert_0<d(A)$$

$$2\lVert\eta\rVert_0+s<d(A_0)$$

完整性方面，单个普通封印只公开 12 种子类型，因此一次新输入发生可见碰撞的主项约为 `1/12`，并附加密码学摘要碰撞项。组封印把两个普通封印绑定后，可把“区段与区段对均未报警”的概率压到两个 Q12 碰撞项的乘积量级，但论文没有为终止封印给出同样完整的全局概率界。

## 5. 实验设置

| 维度 | 设置 |
|---|---|
| Agent | SWE-agent、OpenHands、OpenDev |
| LLM | DeepSeek V4 Flash、GPT-5 mini、MiniMax M3 |
| 任务 | SWE-bench Python、SWE-PolyBench Java、SWE-PolyBench JavaScript |
| 主实验 | 每个对齐 Agent–LLM 条件 3 个种子，每个种子 50 个任务 |
| 对照 | No-WM、ActHook-style、AgentMark-U、Owner-only、完整 TrajMark |
| 所有权标签 | 6 bit，实验标签为 `0x3f` |
| 攻击 | 随机插入、删除、替换；精确预算白盒载体删除；完整性单点与比例攻击 |
| 指标 | 精确 ID 恢复、ACCEPT/REJECT/ABSTAIN、检测率、定位覆盖、动作开销、Pass@1 |

所有权的基本单位是同一密钥、配置和标签下的轨迹批次；完整性的基本单位是一条轨迹及其受保护区段。二者不能混为“单轨迹身份识别”。

## 6. 主要实验结果

### 6.1 所有权恢复与抗破坏性

- 跨 Agent、模型提供方和任务族的 Owner-only 网格中，27/27 个批次准确恢复 `0x3f`；完整水印的 27 个 Agent–provider–seed 组也全部恢复正确。
- 在 20% 随机破坏下，Owner-only 与完整 TrajMark 的精确恢复率分别为 99.3%–100% 和 96.3%–100%；50% 破坏时最低分别为 79.1% 和 76.5%。
- 白盒物理删除更困难：20% 载体删除时分别恢复 22/27 与 23/27 个批次，30% 时降至 7/27 与 10/27，50% 时仅为 0/27 与 1/27。
- 文件名索引比位置索引更抗插入，因为插入动作不会改变已有 basename 槽位身份；但当攻击者准确知道载体并定向删除时，优势明显缩小。

### 6.2 篡改检测与定位

对满足协议条件的穷举单点编辑，九个 Agent–LLM 条件中的检测率为 95.5%–100%。随机单动作 payload 破坏中，95.8% 的修改点被定位到一个被接受的协议区段。这里的“定位”是区段级或协议单元级，不是逐动作精确定位，也不能恢复被删除的内容。

### 6.3 效用与开销

Owner-only 不新增动作。完整 TrajMark 因显式封印增加动作；论文报告 SWE-agent 平均增加约 6.98 个可见动作，结构开销约 22.1%。总体 1,350 次运行中，TrajMark 的 Pass@1 为 26.9%，No-WM 为 26.3%，差异为 +0.6 个百分点；九个条件的符号检验不显著。由于各方法是独立在线运行，而非在同一条固定轨迹上后处理，这一结果只能说明没有观察到系统性质量下降，不能证明逐任务输出完全等价。

## 7. 消融、边界与复现观察

- 所有权密度 `p_o` 控制证据量与干预频率；论文选择能让九个开发条件全部通过的最小密度 30%，并要求批量大小至少 30 时恢复率达到 0.970。
- 6-bit 标识只支持 64 个候选，穷举成本很低，但部署空间有限；扩大容量需要更多独立方程或外层纠错码。
- Q12 封印的结构成本可精确计算，但模型 turns 和 token 还受随机生成、重试与服务调度影响，不能直接当作纯水印成本。
- 论文提供跨框架 adapter 契约、配置和伪代码，但未给出可核实的官方公开仓库，复现仍需自行实现 wrapper、规范化器与攻击协议。

## 8. 论文的主要贡献

1. 明确区分“稳健归属”和“脆弱完整性”，把过去单一行为水印拆成两个协议层。
2. 设计不增加动作的自然 READ 所有权载体，并用文件名而非绝对位置建立稳定槽位。
3. 用普通、组和终止封印把局部区段、相邻区段对和后缀分别绑定，实现可解释的分层告警。
4. 将 ACCEPT、REJECT 与 ABSTAIN 分开，避免证据不足时给出过强结论。
5. 在三个独立 Agent 框架上验证了跨实现可移植性，而不是只针对单一工具接口。

## 9. 局限性与批判性分析

第一，TrajMark 保护的是公开规范投影，不是完整轨迹语义。只要攻击保持关键动作类别、目标和 Q12 计数等投影不变，仍可能大幅改写命令或观察内容而不触发完整性告警。

第二，完整性封印是显式附加 READ，既产生约 22.1% 的结构开销，也给攻击者提供了可识别的协议形态。论文只对固定、单次或有限攻击进行证明与实验，未覆盖基于重复发布、验证反馈或语义压缩的自适应移除。

第三，所有权是批次级结论。把多条轨迹合并后恢复标签，不等价于证明批次中每一条轨迹都来自同一部署；混合标签批次本身也被排除在威胁模型之外。

第四，对称密钥结构不提供公开可验证性和不可抵赖性。密钥持有者既能验证也能伪造，因而更适合作为服务商内部取证机制，而不是第三方争议中的独立证据。

第五，标识容量只有 6 bit，完整性可见碰撞空间只有 12 种子类型。设计强调低成本和跨框架可实现性，但若用于大规模多租户与强对抗场景，需要更大载荷、外层纠错、密钥轮换和上下文签名共同补足。

## 10. 复现建议

1. 先固定公开规范化规则和 adapter 版本，再实现水印；任何字段归一化差异都会导致回放不一致。
2. 分开验证 Owner-only 与完整 TrajMark，分别报告批次 ID 恢复和单轨迹定位，不要用一个检测率替代两者。
3. 保留 ACCEPT、REJECT、ABSTAIN 三类统计，并报告矩阵秩、有效 basename 槽位数和唯一最优候选。
4. 在攻击实验中区分随机动作删除、随机载体删除和知道真实载体的白盒删除；三者难度不同。
5. 增加投影保持型语义改写、跨轨迹拼接、混合标签批次、验证 oracle 和多轮自适应压缩，检验论文明确未覆盖的边界。
6. 效用测试应采用相同任务、种子和测试 harness，并分别报告动作数、模型调用数、token 与 Pass@1。

## 11. 对后续研究的启发

TrajMark 最值得借鉴的不是 Q6 或 Q12 的具体编码，而是“不同安全目标使用不同统计性质的信道”。在语音、图像或生成模型中，也可以把稳健版权标识与脆弱篡改定位分离：前者跨片段冗余聚合，后者绑定局部时间窗或语义单元。另一个重要启示是显式设置 ABSTAIN：当攻击清除了证据时，可靠系统应承认无法判断，而不是强制二分类。

## 12. 一句话总结

TrajMark 用不增动作的自然 READ 方程回答“这批编码 Agent 轨迹属于谁”，再用显式链接封印回答“哪一段被改过”，其设计清晰且跨框架，但结论严格限定在对称密钥、批次归属和公开投影完整性范围内。

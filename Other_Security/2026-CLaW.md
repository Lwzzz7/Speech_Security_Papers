# CLaW：面向扩散图像溯源的 Codec 引导自适应潜空间水印

## 0. 翻译摘要原文

随着文本到图像扩散模型的快速发展，越来越逼真的人工智能生成内容引发了有关滥用和版权侵权的严重担忧。数字水印能够实现用户级溯源，是一种有前景的解决方案，但现有方法仍难以大规模部署，原因包括昂贵的模型重新训练或检测成本、不理想的有效性与保真度权衡，以及对图像变换的鲁棒性有限。

为解决这些问题，本文提出 CLaW（Codec-guided Latent Watermarking），一种面向可溯源扩散图像生成的鲁棒高效水印框架，使用冻结的扩散主干，并且检测无需反演。具体而言，CLaW 首先使用预训练水印编解码器，将每个水印消息映射为潜空间残差，从而实现低成本的采样时注入。随后，在去噪后期窗口内注入残差；此时图像语义能够更好地保留，水印信号也较少受到后续去噪更新的扰动，从而在水印有效性和图像保真度之间取得更好的平衡。

此外，作者引入解码器引导的自适应注入机制，将解码置信度作为反馈，动态校准水印强度，增强较弱的水印信号，并提高图像变换下的鲁棒性。大量实验表明，CLaW 保持了较高的视觉保真度，并在图像变换下取得先进的鲁棒性表现，实现可靠的用户级溯源。

## 1. 方法动机

### 1.1 为什么需要用户级水印

论文面向图像生成平台：平台给每个注册用户分配不同的二进制消息，生成时将其写入图像；图像经过传播、编辑和转存后，监管方或平台从可疑图像恢复消息，与用户数据库比对。目标不只是判断“是不是 AI 图像”，还要识别“来自哪个注册用户”。

这意味着检测是否存在水印与完整消息恢复是两个层次。二分类分数很高，但恢复 bit 不够准确时，大规模用户匹配仍可能失败或错配。

### 1.2 现有方法的具体代价

初始噪声水印可保持生成模型不变，但不少方法需要扩散反演才能检测，单张图像审计较慢；改变初始噪声也可能使同 prompt、同 seed 的图像布局发生明显变化。修改 VAE、训练 LoRA 或增加生成模块的方法可以直接解码，但需要更新模型或为不同生成器维护专门组件。

后处理水印无需改生成器，但水印在最终 RGB 上写入，仍需面对裁剪、遮挡、恢复处理和重生成等干扰。本文尝试保留图像端直接解码的便利，同时将写入位置移动到生成过程内部。

### 1.3 核心 insight

已经训练好的 latent 水印 codec 能给出“什么方向的潜空间扰动可以被图像解码器读出”。无需再训练扩散主干，可以直接沿这个方向扰动采样状态。

但注入时机很重要：早期扰动要经过长串后续更新，既可能改变布局，也可能被去噪过程削弱；末段更接近 codec 预训练时见到的干净 latent。不同 prompt 的可解码程度又不同，因此用冻结解码器对中间结果做预览，对置信度不足的轨迹增加强度。

## 2. 威胁模型解读

### 2.1 参与方与权限

平台控制采样器中间 latent，可以运行水印编码器、访问 VAE 解码器，并在指定采样步注入残差。用户通过平台生成图像，外部传播者可以对已生成图像做编辑或信道变换。验证方持有冻结水印解码器、注册消息库和接受阈值，从可疑 RGB 图像直接恢复 bit。

方案需要生成服务主动配合，不能仅从一个不暴露采样过程的第三方黑盒 API 给生成过程内部加水印。检测不需要原始 prompt、初始 seed 或原图，也不需要执行扩散反演。

### 2.2 攻击目标与实际能力

实验主要测试传播者对图像的后处理是否能使检测失败或阻碍用户归属，包括压缩、裁剪、模糊、噪声、亮度、遮挡、涂画、复合处理、超分、去噪、截图、屏摄和有限强度再生成。

这些主要是图像数据级、生成后攻击。论文没有系统测试攻击者持有秘密 decoder 后，针对其梯度优化移除水印；也没有建立攻击者拿到完整生成管线后不能关闭注入的白盒保护保证。冻结模型易部署，不代表水印模块不可绕过。

“Adaptive Noise”是评测套件中的内容自适应局部噪声，不能据名称将其理解为了解水印模型、根据检测反馈迭代优化的自适应安全攻击。

### 2.3 攻击约束与验证目标

常规攻击使用固定强度；屏摄包含显示、相机捕获带来的实际几何和色彩变化。再生成设置为 strength 0.15、20 步、guidance 4.5，使用数据集 prompt。本文不能据这个单点结果推断强重绘、未知提示词编辑或所有生成式移除都可抵抗。

用户级验证在数据库中找最佳 bit 匹配，达到阈值才接受。二项空假设要求无关图像的解码 bit 对固定消息近似独立、每位匹配概率为 1/2；对百万候选取最大值又引入多重比较。因此论文同时报告经验注册库级 FPR，这比只引用单码字理论概率更贴近实际归属。

### 2.4 知识、密钥与系统外边界

作者称 codec 为 secret encoder/decoder，但没有给出标准密码学私钥签名、密钥轮换或抗串谋协议。48-bit 用户消息是数据库标识，并不天然构成数字签名。本文主要证明可恢复性与误归属控制，没有充分覆盖伪造目标身份、移植水印、用户串谋、数据库泄露或恶意注册。

现实部署还需要保护用户—消息映射、处理同分候选及重复注册、审计阈值与认证记录。将水印解码结果直接用于处罚用户，需要额外系统证据。

### 2.5 方法怎样回应威胁模型

攻击增强 codec 负责学常见图像扰动下可恢复的方向；晚期注入避免信号在长去噪路径中消失；置信度反馈强化弱样本；末端 anchor 作最终补强；注册库阈值拒绝弱匹配。它们共同服务于内容分发后的追踪，未直接服务于公开模型权重下的不可移除性。

## 3. 方法设计与复现级理解

### 3.1 三阶段全局流程

离线训练：COCO 图像与随机 48-bit 消息 → 冻结 VAE 编码图像 → 水印编码器只根据消息生成残差 → 在干净 latent 上相加 → 冻结 VAE 解码 → 随机攻击增强 → 水印解码器恢复消息 → 联合优化水印恢复与视觉正则。

在线生成：prompt、seed、用户消息 → 正常生成直到最后 10% 步数 → 将消息残差换算至采样器尺度 → 预览当前 latent 的目标消息置信度 → 更新强度增益 → 先加残差，再执行标准采样更新 → 末端加小 anchor → 输出图像。

归属检测：可疑 RGB 图像 → 一次水印 decoder 前向 → 得到 48-bit 估计 → 与用户库匹配 → 达阈值接受，否则拒绝。只有 codec 在离线训练；文本编码器、扩散主干、采样器和原生 VAE 均不为水印更新。

### 3.2 阶段一：训练可跨消息复用的 latent codec

对应 3.1。干净图像先经过 VAE，得到 latent；水印编码器以消息为输入，输出同接口的残差。编码器并不读取当前图像或 prompt，因此它学到的是消息相关方向，而不是逐图像优化残差。

$$z=E_{vae}(x_0),\qquad x'_0=D_{vae}(z),\qquad \delta_s=E_s(b),\qquad x_w=D_{vae}(z+\delta_s).$$

图像保真正则比较的是水印图像与 VAE 重建图像，而不是原始输入图像。这样可以把 VAE 自身的重建损失与新增水印失真分开。训练时可通过冻结 VAE 的计算图把梯度传回水印编码器，冻结参数并不等于切断其输入梯度。

水印 decoder 输出每个 bit 的两类 logits。论文式 (1) 使用两类 logit 各自 sigmoid 的正负监督，而预览置信度用两类 softmax；这是两个不同公式接口，复现不能默认完全相同：

$$L_{WM}=-\frac{1}{2K}\sum_{k=1}^{K}\left[\log\sigma(s_{k,b_k})+\log\left(1-\sigma(s_{k,1-b_k})\right)\right],\qquad s=D_s(A(x_w)).$$

其中 $K=48$，$A$ 是随机增强，正确类别 logit 应提高、错误类别应降低。训练先仅使用 bit 损失，让 decoder 能读出消息，再加入视觉约束：

$$L=L_{WM}+5.0L_{LPIPS}(x'_0,x_w)+1.5L_{PRVL}(x'_0,x_w).$$

LPIPS 约束感知差异；PRVL 来自 AquaLoRA，限制峰值区域变化，避免局部明显失真。本文没有重新完整定义 PRVL 计算式及 codec 全部网络层，需要对齐引用实现，不能自行替换成普通全图 MSE 后仍称忠实复现。

每个 batch 采样图像和随机消息，前向经过编码、残差、VAE 解码和增强，计算三项损失，反向仅更新 $E_s,D_s$。训练完成后二者冻结。增强包含 identity、JPEG simulation、crop-resize、Gaussian blur/noise 和 color jitter。不同阶段的具体 epoch 分界及增强概率，当前正文和附录没有完整给出。

### 3.3 阶段二准备：把 VAE 残差换算为采样器残差

对应 3.2、附录 B.2。codec 在 VAE latent 中学到残差，而 SD3.5、FLUX 的采样状态采用模型对应的尺度与布局。直接把未换算的残差加进去，强度会错位。

$$\bar\delta_s=s_{vae}\delta_s.$$

需要时先双线性缩放残差至目标 latent 空间分辨率，再乘 VAE scaling factor。VAE shift 不加到残差上，因为加性残差是两个状态的差，常量偏移会抵消。最终 VAE 解码和预览则仍应按生成管线正确还原状态的尺度与 shift。

FLUX 还存在 packed latent。注入必须对齐实际采样器张量的 pack/unpack、通道和空间坐标；不能只把四维残差 reshape 成三维就假定正确。论文说明兼容 packed 管线，但未给出完整布局转换代码及 codec 跨 VAE 的详细权重接口。latent 通道数、VAE 版本与 scaling 值应从对应模型配置核验，不在这里补造。

### 3.4 晚期窗口：明确在采样更新之前注入

令 $i$ 按实际推理顺序从 0 增至 $N-1$，而不是直接用扩散时间数值判断早晚：

$$i_s=\lfloor\rho_sN\rfloor,\qquad i_e=\lceil\rho_eN\rceil,\qquad W=\{i_s,\ldots,i_e-1\}.$$

默认 $N=50$、窗口 $(0.9,1.0)$，因此在索引 45–49 的 5 次更新前注入。其余步完全沿原采样流程。基础形式为：

$$\tilde z^{(i)}=z^{(i)}+\alpha w_i\bar\delta_s,\qquad z^{(i+1)}=S_{\theta}(\tilde z^{(i)},\tau_i,c),\qquad i\in W.$$

窗口外残差为零。$S_{\theta}$ 包含当前模型预测与 scheduler 更新，$c$ 是文本条件。先加残差再调用更新，与先 denoise 再叠加是不同算法。

直觉是最后几步更接近 codec 的干净 latent 训练域，信号需要经过的后续更新少，主语义也已形成。附录一阶分析写出偏差递推：

$$\epsilon^{(i+1)}\approx J_i\left(\epsilon^{(i)}+\alpha_i\bar\delta_s\right),\qquad J_i=\frac{\partial\Phi_i(z^{(i)};c)}{\partial z^{(i)}}.$$

早期注入经过更多后续 Jacobian，可能衰减或影响语义。该分析是局部近似：不能仅凭 Jacobian 链更短就严格证明所有晚期注入都更鲁棒或更保真；图 3 与消融提供经验支持。

### 3.5 时间权重：归一化控制基础预算

窗口内用局部索引 $j=0,\ldots,L-1$ 计算原始权重，再归一化。平坦原始权重为 1，线性为 $j+1$，余弦为：

$$\bar w_j=1-\cos\left(\frac{j+1}{L}\frac{\pi}{2}\right),\qquad w_j=\frac{\bar w_j}{\sum_{m=0}^{L-1}\bar w_m}.$$

默认线性调度，在 5 步窗口内权重为 $(1,2,3,4,5)/15$。因此改变步数不会直接把基础累计注入变成“每步同强度重复 L 次”。但归一化只固定基础权重和，加入自适应增益与末端 anchor 后，总有效扰动预算仍会变化。

### 3.6 解码器反馈：预览当前状态，动态重设增益

对应 3.3。固定强度可能对容易样本浪费失真预算，对困难样本又不足。作者在选定窗口步将当前 latent 还原为预览 RGB，运行冻结 decoder，求其对目标消息的平均置信度：

$$x_{pre}^{(i)}=D_{vae}(z^{(i)}),\qquad P_m(i)=\frac{1}{K}\sum_{k=1}^{K}\frac{\exp(q_{k,b_k})}{\exp(q_{k,0})+\exp(q_{k,1})},\qquad q=D_s(x_{pre}^{(i)}).$$

公式省略了预览解码所需的 scheduler 尺度还原。这里预览的是当前步注入前的状态，也不是先预测干净 $z_0$ 再解码，不能自行替换成另一个预览定义。

默认每步预览，目标置信度 0.98。将 gap 转成增益，再限制范围：

$$g_i=\min\left(g_{max},\max\left(g_{min},1+\lambda\max(\tau-P_m(i),0)\right)\right).$$

默认 $\lambda=2$、$g_{min}=0.75$、$g_{max}=1.5$。当置信度 0.90 时，增益为 1.16；置信度达标时为 1；gap 很大时截到 1.5。因为默认下公式未裁剪值总不小于 1，0.75 的下限实际不会被用到。

这里每次从“1 + 当前 gap”重新计算，不是把增量加到上一增益上，也不是一旦增大就永不降低。未到预览步时复用上次增益，初始值为 1。预览周期 $s_{pre}$ 决定计算开销，默认 1。

$$\delta_i^{ada}=\alpha w_i g_i\bar\delta_s,\qquad \tilde z^{(i)}=z^{(i)}+\delta_i^{ada}.$$

控制器只改变固定残差方向的幅度，没有在线梯度优化，也不计算附录分析中的置信度梯度。它检查的是无攻击预览的目标 bit 概率，不是每步把各种攻击都跑一遍；攻击鲁棒性来自 codec 训练与该反馈策略的经验效果，并非反馈直接优化所有攻击后的最坏情况。

### 3.7 Terminal anchor 与最终输出

完成所有采样更新后，再给最终 latent 加一次小残差：

$$z_{final}=z^{(N)}+\gamma\bar\delta_s,\qquad x_w=D_{vae}(z_{final}),\qquad\gamma=0.1.$$

这一次不再经过扩散更新，直接提供末端读出补强，因此也可能增加失真。它与窗口注入是不同位置，消融应分别考虑。附录 B.1 的 anchor 符号写为 $\Delta_M(b)$，正文与算法给出的可执行定义是同一消息对应的 scheduler-space 残差；复现应统一单位。

### 3.8 检测与用户归属：先恢复 bit，再接受或拒绝

可疑图像经过 decoder 后每位取最高 logit 类别，形成 $\hat b$。与每个用户消息计算 Hamming 匹配数，再找最大值：

$$M(b,\hat b)=\sum_{k=1}^{K}\mathbb{I}[b_k=\hat b_k],\qquad \hat u=\arg\max_{u\in U}M(b^{(u)},\hat b).$$

只有最佳匹配数不小于阈值 $\kappa$ 才接受，否则拒绝。decoder 一次前向无需反演，但用户库搜索还有成本；文中约 10 ms 的检测时延不能无条件解释为百万码字库完整检索的总耗时。

对固定候选码字，论文用随机独立匹配假设选阈值：

$$p_{single}(\kappa)=\sum_{j=\kappa}^{48}\binom{48}{j}2^{-48}.$$

这个式子不是注册库级误报率。对 $|U|$ 个候选，联合界为 $p_{registry}\leq |U|p_{single}$，这属于根据论文设定作出的统计推论。真实 bit 相关性、码本分布与最大匹配搜索都需要经验校准。正文因此使用独立未水印图像划分来设置、测试阈值。

### 3.10 复现风险与机制限制

最容易出错的是 residual 的尺度、FLUX packing、预览发生在注入前还是后，以及 anchor 使用的单位。其次是 softmax 置信度与训练 sigmoid 双 logit 损失的区别。权重归一化、增益重算、非预览步保持值都应严格按算法处理。

附录一阶 Jacobian 与语义/水印子空间弱耦合分析提供解释，依赖局部线性、小扰动与晚期弱交互的近似，不是经过证明的鲁棒性定理。作者 Checklist 也说明未声明定理。codec 预览在当前分布上置信度高，不保证所有攻击后仍高；极高置信度还可能存在校准误差。

| 方法路线 | 核心思想 | 优点 | 主要代价与边界 | CLaW 的区别 |
|---|---|---|---|---|
| RivaGAN 后处理 | RGB 端学习消息嵌入 | 不改生成器，可直接解码 | 恢复处理、复合攻击仍可破坏 | 在生成末段 latent 中写入 |
| Tree-Ring/RingID 等噪声水印 | 初始噪声结构编码 | 与生成过程结合紧密 | 多依赖反演；几何变化影响检测 | codec 图像端单次解码 |
| Gaussian Shading 等 | 采样分布保持的噪声编码 | 分布性质与较强部分攻击鲁棒性 | 噪声变化使同 seed 图像不同；反演有成本 | 固定原始噪声，末段加残差 |
| Stable Signature | 微调 VAE decoder | 图像端读取固定签名 | 需改变 decoder；多用户部署受实现限制 | 原生 VAE 冻结 |
| AquaLoRA | codec 后再训练水印 LoRA | 消息可更新；考虑白盒模型保护 | 需要主干 LoRA 训练 | 借用 codec 思路，取消生成器训练阶段 |
| SERUM | 初始噪声模式与独立 detector | 无反演检测 | 多模式 detector 组织与用户扩展不同 | 共享 decoder 直接输出 48-bit |
| CLaW | 晚期残差 + 置信度反馈 | 快速消息恢复、高同 seed 保真度 | codec 预训练、采样接口控制、额外预览 | 本文方案 |

贡献主要是将预训练 codec 残差、末段注入和无梯度反馈组成生成时控制框架，不是发明新的消息编解码原理。它适用于平台可控制采样、需要大批用户标识且希望审计快速的场景。它没有继承 AquaLoRA 所讨论的白盒不可绕过目标。

## 5. 实验表现与优势

### 5.1 主实验：同时衡量检测、保真和耗时

作者在两个现代 flow-matching 图像主干上各生成 1,000 张图，使用共同 prompt 与 seed。F1/accuracy 判断水印与无水印，BitAcc 衡量消息恢复，PSNR 比较同 prompt/seed 的配对图，FID 比较生成分布与 COCO。各指标测的不是同一属性。

| 指标 | SD3.5-medium | FLUX.1-dev |
|---|---:|---:|
| Clean F1 | 1.0000 | 1.0000 |
| 八攻击平均 F1 | 0.9922 | 0.9968 |
| PSNR | 41.25 dB | 41.06 dB |
| FID | 35.70 | 38.37 |
| 生成时间 | 1.9339 s | 4.7331 s |
| decoder 检测时间 | 0.0115 s | 0.0104 s |

表 11 的 clean 生成时间分别为 1.8341 s 与 4.6072 s，由表中均值可算额外约 5.4% 与 2.7%。CLaW 检测相对秒级反演方法显著更快。生成并不是全部方法中最快，关键是接近 clean 且检测很快。

PSNR 高说明相对同 seed 干净输出变化小；对于通过改初始噪声保持分布的方案，低配对 PSNR 也可能表示生成了另一张合理图片，不能把它单独解释为图像绝对质量差。表 12 中 CLaW 的 FID 也不是所有方法最好，SD3.5 的 SSIM 0.9427 低于 RivaGAN 0.9820。应说综合权衡好，而不是每个质量指标全面最优。

### 5.2 常规图像变换：裁剪收益尤其突出

表 2 在 SD3.5 上测八类攻击。CLaW crop-resize F1 为 0.9970，SERUM 为 0.9224，Gaussian Shading/GaussMarker 为 0，WIND 为 0.0271。这是本文平均鲁棒性优势的重要来源。

JPEG、blur、mask、overlay 的 F1 分别为 0.9995、0.9995、0.9985、0.9970；brightness 为 0.9616，低于部分基线的 1.0。FLUX 平均 F1 为 0.9968，crop-resize 为 1.0。它没有在每个单攻击上获胜。

附录表 8/9 的平均 BitAcc 为 0.9590/0.9688，明显低于接近 1 的 F1，说明“检测有水印”和“每位全部恢复”不可等同。图像检测几乎完美时，仍可能存在足以影响大规模归属的 bit 错误。

### 5.3 复合攻击与恢复处理：超越单一信号变换

表 4 包括 blur+noise+JPEG、brightness+overlay+JPEG、crop-resize+JPEG，各做一次和三次；另有 Real-ESRGAN 4×、超分后下采样一次/三次，以及 SwinIR 去噪，总计十条件。

CLaW 总平均 F1 为 0.9066，高于 WIND 0.8071、Gaussian Shading 0.7969。分组 F1 为 degradation 0.9873、editing 0.8293、geometric 0.8030、super-resolution 0.9473、denoising 0.9848。

优势主要是几何处理没有像若干噪声水印一样完全失效；editing、restoration 下部分基线反而更高。因此“综合更均衡”比“对复合攻击处处最强”更符合表格。SwinIR 使用 sigma 15 的预训练模型，但没有先向输入额外加噪，属于用恢复网络处理水印图本身。

### 5.4 截图与屏摄：真实捕获信道

作者各测 100 张图，直接读取桌面截图或手机拍摄屏幕所得图像，不做人工裁剪与几何校正。平均 BitAcc 分别为 99.04% 和 84.21%。截图近乎保留全部消息，而屏摄引入更多几何、色彩和成像失真。

84.21% 是 bit 平均，不是 84.21% 的用户能被正确识别；也不能自动推导满足 44/48 接受门限。论文未给这组屏摄的完整百万用户归属率，不能用该 bit 数字替代实际用户级指标。设备、拍摄角度和光照覆盖范围仍影响推广结论。

### 5.5 再生成：可检测但并非最好

表 10 的固定低强度去噪再生成后，CLaW 在两个主干的 F1 均为 0.9744，BitAcc 分别为 0.9396 与 0.9177。GaussMarker 相应 F1 为 1.0/1.0，BitAcc 为 0.9973/0.9439，优于 CLaW。

这个结果支持 CLaW 在所测再生成点保持较强读出能力，而不是再生成鲁棒性全面领先。扩大 strength、换再生成模型、进行目标化编辑或多轮攻击，需要另外评估。

### 5.6 用户追踪：从检测扩展到百万候选搜索

表 5 使用不同的 48-bit 用户消息，在一万、十万、百万注册用户中匹配。百万用户时，SD3.5 的 clean/attacked Trace Acc 为 99.80%/96.49%；FLUX 为 100%/98.03%。RivaGAN 的 attacked 分别为 85.70%/89.35%。

正文另设开放集误归属实验：6,000 张无水印图用于设置门限，另一组 6,000 张负例加 1,000 张携带不同消息的水印图用于测试，报告五次运行平均。44/48 门限下注册库级 FPR 为 0.0500%，Trace Acc 为 98.5%；45/48 时 FPR 为 0.0100%，Trace Acc 为 97.3%。

表 5 与开放集实验的样本、门限协议不同，不应将 99.8% 与 98.5% 写成同一设置的互相矛盾结果。门限收紧减少误归属，同时拒绝更多真水印图，是部署时真实的风险权衡。

### 5.7 消融：最关键的是注入时机

表 6 去掉 late denoising 后，SD3.5/FLUX 的 attacked BitAcc 仅为 0.5413/0.5727，接近无效；PSNR 却升至约 57.5 dB。这说明高保真可能来自水印根本没有留下，而不是更好的有效水印。

去掉 adaptive feedback 时 attacked BitAcc 为 0.9283/0.9384，full 为 0.9595/0.9695，增益约 3.12/3.11 pp；去掉 anchor 为 0.9521/0.9604，说明 anchor 提供较小补强。full 的 PSNR 相应下降，提升恢复确实消耗一定失真预算。

表 14 比较 flat/linear/cosine，在同窗口与控制器下 cosine attacked BitAcc 最好：SD 0.9629，FLUX 0.9723；linear 为 0.9598/0.9681。作者默认 linear，强调保真与鲁棒折中，但部分 PSNR 差异很小，不应描述为显著优势。

不同表的 full 数值并不完全一致：表 1/12 的 SD PSNR 41.2460，表 6/14 的 full/linear 约 40.04；attacked BitAcc 也有小差异。本文没有清楚解释这些设置或样本口径变化，精读按表分别引用，不把它们拼为同一次运行。

## 6. 学习与应用

### 6.1 开源与复现起点

当前 PDF 的 Checklist 说明提交时代码未公开、计划接收后开源；本次核查未找到可确认的官方 CLaW 仓库。论文信息只给 Paper，不使用推测代码链接。复现应先获取 AquaLoRA 风格 codec 的完整架构与 PRVL，跑通干净 latent 的 48-bit 恢复，然后接入一个 backbone 的末段固定注入，最后加入反馈与 anchor。

先验证单张图像的 VAE/scheduler 尺度和 FLUX packing，再跑规模实验。应分别记录基础残差范数、每步 gain、预览置信度、最终 bit accuracy、配对失真以及额外 VAE decoder 调用次数。

### 6.2 应补的实验证据

固定与自适应控制应尽量在同等累计扰动预算下比较，否则部分提升可能仅来自注入更强。还可测预览概率与最终受攻击消息恢复的相关性、不同 preview stride 的时延收益，以及去掉窗口注入只留 anchor 的对照，厘清采样耦合的实际贡献。

部署层面要测用户库规模增长的检索时延、真实负例的 bit 相关性、码字最小距离、同分处理，以及针对 decoder 的自适应移除和目标身份伪造。这些是后续建议，不是论文已经完成的验证。

### 6.3 对语音生成水印的启发

可借鉴“冻结生成器 + 预训练 latent codec + 后段置信度反馈”。语音中需要先确认生成 latent 与 codec 训练 latent 的接口一致，再区分当前解码置信度与压缩、声码器、VC/ASR-TTS 后的恢复能力。图像末段语义稳定的经验不能自动迁移成语音后段对所有再合成都鲁棒。

如果增加反馈，必须把预览音频的 decoder 成本纳入实时性，并关注时序拼接、帧尺度、听觉失真与消息同步。本文没有提供语音实验。

## 7. 总结

晚期注入残差，解码反馈调强度。

## 9. 复现难度与适合人群

难度为中到高。算法控制环很简单，主要难点是 codec 权重与架构、VAE latent 通道/尺度、FLUX packing、攻击库和基线适配。完整比较需要 H100 级别硬件及大量图像生成，codec 40 epoch 也有训练成本。

最小版本先做单主干、固定消息、50 steps、末 5 步线性注入，比较无水印、只 anchor、固定 late window、自适应 full。再加入随机消息、crop/JPEG、多个用户匹配，最后测开放集误归属。适合图像生成水印、推理时 latent 控制、平台内容溯源与语音生成水印迁移研究者。

## 10. 简短全面总结

CLaW 面向扩散图像平台的用户级溯源，试图同时降低生成器适配与检测开销，并保持传播变换后的消息恢复。方案先在冻结 VAE 上训练 48-bit 水印 codec，将消息映射为 latent 残差；生成时保持主干与 codec 冻结，在最后 10% 采样步按归一化调度注入残差，用中间预览的目标消息置信度调整增益，最终再以小 anchor 补强。检测只需图像端 decoder 前向，再将消息与注册库匹配并按门限拒绝弱归属。在 SD3.5-medium 与 FLUX.1-dev 上，平均常规攻击 F1 为 0.9922/0.9968，PSNR 约 41 dB，检测约 10 ms；百万用户下受攻击追踪率达 96.49%/98.03%。其优势是冻结生成器、直接读取消息与较均衡的鲁棒保真折中；但仍需预训练 codec 和受控采样接口，当前结果不构成对白盒绕过、身份伪造或任意强再生成的保证。

## 11. 论文写作逻辑分析

### 11.1 问题铺垫与 insight

引言把应用目标从 AI 内容识别缩小到用户级归属，再列训练、检测、保真和鲁棒四个部署障碍。方法对应关系明确：codec 复用降低适配成本，图像端 decoder 降低检测成本，late window 保持语义与信号，反馈控制处理样本差异。

更值得学习的是给已有 codec 一个新的生成接口，而不是声称所有组件都是新发明。与 AquaLoRA 的关系应理解为共享预训练思路、改变第二阶段实施方式与保护目标。

### 11.2 方法叙事与威胁模型承接

方法按“学可读方向—放在哪—放多少—怎样追踪”推进，理解顺畅。附录补充 scheduler 尺度、调度、anchor 和控制器算法很必要。不过 threat model 主要隐含在攻击清单里，若在正文明确平台控制权、攻击者是否知道 decoder、是否允许白盒关闭模块，安全主张会更清楚。

### 11.3 实验呼应与不足

主表给综合指标，随后分常规攻击、复杂信道、用户库和消融，基本对应前述动机。用户级目标还用开放集负例实际校准，避免只停留在 BitAcc，是有价值的实验组织。

应进一步统一不同表的 full 配置口径，补码本搜索时延与固定预算自适应对照。屏摄应接到身份级指标，再生成应扩成强度曲线，理论段应明确是近似机制分析。这样可以减少“接口便利、经验鲁棒、密码学安全”之间的概念跨越。

### 11.4 可以借鉴的写法

把训练与部署分开，把控制器写成可执行状态更新，再用针对性消融定位时机与增益的贡献。对于后续语音水印论文，可类似围绕“在哪里注入、怎样适应难样本、检测和归属如何衔接”组织叙事，同时逐项报告代价与威胁模型边界。

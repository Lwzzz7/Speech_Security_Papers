# MOLM：Mixture of LoRA Markers

## 0. 翻译摘要原文

生成模型能够大规模生成逼真的照片级图像，这引发了严重担忧：我们是否能够检测合成图像，并将这些图像归因到具体来源。虽然水印被视为一种可能解决方案，但现有方法面对真实失真时仍然脆弱，容易受到自适应移除攻击，而且当底层水印密钥变化时更新成本很高。本文提出一种通用水印框架，将编码问题表述为生成模型参数的密钥依赖扰动。在该框架内，作者提出 Mixture of LoRA Markers（MOLM）：一种基于路由的实例化方法，其中二进制密钥会激活残差块和注意力块内部的轻量低秩适配器（LoRA）。这种设计避免了针对每个密钥重新训练，并实现了不可感知性、保真度、可验证性和鲁棒性等目标。Stable Diffusion 和 FLUX 上的实验表明，MOLM 能保持图像质量，同时在失真、压缩和再生成、平均攻击以及针对提取器的黑盒对抗攻击下实现鲁棒密钥恢复。代码可见：https://github.com/Samar-Fares/MOLM-Watermark。

## 1. 方法动机

文本到图像扩散模型已经可以稳定生成高质量、逼真的图像。模型所有者和平台面临两个问题：第一，给定一张图像，能否判断它是否由某个生成模型产生；第二，如果系统里有多个用户、多个部署实例或多个密钥，能否把图像归因到具体来源。MOLM 关注的是生成式图像水印中的检测与归因，而不是对任意已有图像做后处理水印。

论文认为已有方法有三类核心痛点。

第一，鲁棒性不足。WAVES benchmark、regeneration attack、averaging attack、surrogate decoder attack、purification attack 都说明，很多不可见图像水印在几何变换、压缩、扩散再生成或自适应攻击下容易失效。Tree-Ring、Gaussian Shading、Stable Signature 等方法各有优势，但在现实失真和自适应移除上仍不稳。

第二，鲁棒性和图像质量冲突。初始噪声、latent trajectory 或 decoder 权重中嵌入水印时，增强可检测性往往会牺牲视觉质量、FID、SSIM 或 PSNR。对模型水印来说，这个问题比普通后处理水印更敏感，因为生成模型输出质量本身就是产品能力。

第三，密钥更新成本高。Stable Signature、SleeperMark、ROBIN、AquaLoRA 等方法往往需要 per-key training、per-prompt optimization、预训练水印模块或重新微调。真实部署里密钥可能对应用户、模型版本、租户或时间周期，如果每换一个 key 都要重训，系统不可扩展。

MOLM 的核心 insight 是：把水印嵌入统一看成“密钥依赖的参数扰动”，而不是必须在图像、初始噪声或 prompt trigger 上做文章。LoRA 天然是轻量参数扰动；如果在多个生成模型 block 中预置多个 LoRA adapter，并让二进制 key 决定每层走哪一个 adapter，就能用“路由路径”承载水印。这样 key 切换只改变 adapter 选择，不改变 backbone，也不需要为新 key 重新训练。

## 2. 威胁模型解读

### 2.1 参与方与系统边界

论文的问题设定包含四类参与方。模型所有者拥有生成模型 $G_{\Phi}$ 和水印系统 $W=(U_{\zeta},V_{\eta})$，负责对用户 prompt 生成带水印图像。用户通过 API 提交文本 prompt，接收生成图像，不知道生成模型参数和水印系统细节。验证者只访问水印提取器 $V_{\eta}$ 和待验证 key 或 key 数据库，用于检测图像是否带有效水印，或归因到具体用户/模型。攻击者试图通过移除或伪造绕过系统。

系统边界内包括冻结生成器、LoRA marker 集合、key routing 规则、提取器和已注册 key。系统边界外包括用户 prompt、公开获得的生成图像、图像编辑/压缩/再生成工具和攻击者自建模型。

### 2.2 攻击者目标

攻击目标分两类。移除攻击中，攻击者从有效水印图像 $\tilde{x}$ 出发，修改它使验证者判为无水印。伪造攻击中，攻击者从真实图像或其他模型生成图像出发，修改它使验证者误判为带目标水印。归因场景下，攻击者还可能希望让图像被错误归因到某个用户或模型。

### 2.3 攻击者能力

论文假设攻击者可以对图像做常见变换，例如 crop、rotation、resize、brightness adjustment、JPEG compression。攻击者还可以做更强攻击，包括 learned compression、diffusion regeneration、averaging attack、针对 extractor 的 PGD attack，以及通过 API 收集一批有效水印图像辅助攻击。

在 white-box extractor attack 中，攻击者知道提取器参数和检测阈值 $\tau$，并在 MSE/PSNR 约束下优化输入图像，使提取器输出接近随机。附录还讨论 full-knowledge 场景：攻击者知道完整 MOLM pipeline、架构、loss 和训练超参数，并可用不同数据子集和随机种子重新训练自己的生成模型。

### 2.4 攻击者知识

主设定中，攻击者可能有关于生成模型和水印类型的高层知识，但不能访问模型参数 $\Phi,\zeta,\eta$。这意味着攻击者不知道 LoRA marker 权重、extractor 参数、具体 key 和路由统计。white-box extractor attack 是更强设定，只开放 $V_{\eta}$ 和阈值；full-knowledge 设定则开放 pipeline 但不共享同一训练运行的参数和随机性。

### 2.5 攻击约束

攻击必须保持图像视觉内容可接受。PGD attack 使用 MSE budget $\epsilon$ 或等价 PSNR 下界约束；论文指出当约束比 PSNR 约 10 更宽松时，图像会出现明显失真。平均攻击则受限于能收集多少水印图像，以及这些图像是否同 key 或异 key。检测/归因阈值由目标 FPR 决定，默认 28-bit key 下，1% FPR 对应 $\tau=20$ matching bits；归因实验中为控制全局 FPR 到 $10^{-3}$，使用更保守的 $\tau=27$。

### 2.6 防御者能力与安全目标

防御者能在模型部署前训练 LoRA marker 和 extractor，并在部署时为每次生成选择或分配 key。防御者不能要求每个 key 单独重新训练，不能显著增加推理成本，也不能明显破坏图像质量。安全目标是同时满足四个性质：imperceptibility、fidelity、verifiability、robustness。检测模式下目标是判断是否含有效水印；归因模式下目标是从 key 数据库中找到最近匹配来源。

### 2.7 现实性评估

该 threat model 对生成式图像服务较现实，因为它覆盖 API 生成、第三方验证、用户级 key、常见图像编辑、压缩、再生成、平均攻击和 extractor 对抗攻击。限制在于：主模型参数对攻击者默认不可见；full-knowledge 场景只验证“独立重训不能伪造同一提取器可读签名”，没有展示攻击者直接窃取 LoRA marker 或 extractor 后的强白盒去水印；也没有覆盖人工重绘、语义编辑、局部 inpainting/outpainting 后的细粒度归因。

## 3. 方法设计与复现级解读

### 3.1 全局框架：把水印编码成密钥依赖的模型参数扰动

论文先把生成式模型写成 $G_{\Phi}:Q\times T\rightarrow X$，其中 $q$ 是随机 latent initialization，$t$ 是文本 prompt，$x$ 是生成图像。水印系统包含 embedding algorithm $U_{\zeta}$ 和 extractor $V_{\eta}$。传统写法是先生成 clean image $x=G_{\Phi}(q,t)$，再把 key $\kappa$ 嵌入得到 $\tilde{x}=U_{\zeta}(x,\kappa)$。MOLM 将这个 wrapper 改写成对生成器参数的扰动：

$$U_{\zeta}(G_{\Phi}(q,t),\kappa)=G_{\Phi+\Delta\Phi(\kappa)}(q,t).$$

这句是论文最重要的抽象。水印不是生成后贴到图像上，而是在生成过程内部由 $\Delta\Phi(\kappa)$ 改变模型路径，从而让输出图像天然携带可提取 key。训练阶段，同一 prompt 和同一 latent 会经过冻结原模型生成 $x$，也会经过 key-perturbed generator 生成 $\tilde{x}$；extractor 从 $\tilde{x}$ 中恢复 $\tilde{\kappa}$；训练优化图像相似性 loss 和 key recovery loss。部署阶段，模型所有者只需给定 key，routing 会选择一组 LoRA marker，生成器直接输出水印图像。

### 3.2 LoRA markers：每个 routing layer 放多个候选低秩适配器

给定生成模型可看作一串 block：

$$G_{\Phi}(\cdot)=(F_{\bar{L}}\circ F_{\bar{L}-1}\circ\cdots\circ F_1)(\cdot).$$

MOLM 从这些 block 中预选 $L$ 个 routing layers。对每个被选 block $\ell$，放置 $P$ 个 LoRA adapters：

$$\{A^{(1)}_{\ell},A^{(2)}_{\ell},\ldots,A^{(P)}_{\ell}\}.$$

训练时所有 adapter 参数都可学习，但一次生成只激活每层的一个 adapter。若第 $\ell$ 层被 key 选择的 adapter index 是 $s_{\ell}$，该 block 的前向变为：

$$h_{\ell}=F_{\ell}(h_{\ell-1})+\alpha A^{(s_{\ell})}_{\ell}(h_{\ell-1}).$$

未选中的 block 仍是普通前向 $h_{\ell}=F_{\ell}(h_{\ell-1})$。这里 $\alpha$ 是固定 scaling factor。直观上，每个 block 像一个多选题，key 的一段 bits 决定选择哪条 LoRA 分支；整条 routing path 就是水印编码。

默认实现中，作者选择 Stable Diffusion VAE decoder 的 14 个 ResNet blocks，每层 $P=4$ 个 adapter。因为 $P=4$ 对应每层 2 bits，所以总 key size 是：

$$M=L\log_2P=14\times2=28.$$

论文也尝试扰动 U-Net，它含 22 个 ResNet blocks、16 个 cross-attention layers 和 16 个 self-attention layers，总容量可到 108 bits；但 U-Net 扰动明显破坏图像细节和边缘，因此主实验选择 VAE decoder。这个取舍说明 MOLM 的容量不是越大越好，载体层越靠近核心 denoising dynamics，质量风险越高。

### 3.3 Key routing：把二进制 key 切成 layer-wise adapter index

给定 $M$-bit key $\kappa$，MOLM 将它切成 $L$ 个不重叠 chunk：

$$\kappa=(\kappa_1,\kappa_2,\ldots,\kappa_L).$$

每个 chunk 长度为 $\log_2P$ bits，并转换成十进制 index $s_{\ell}\in[P]$。于是 key 决定 routing collection $\{s_{\ell}\}_{\ell\in[L]}$，也就决定本次生成激活的 adapter 集合 $\Psi(\kappa)$：

$$\Delta\Phi(\kappa)=\Psi(\kappa)\subset\Psi.$$

这里 $\Psi$ 是所有 LoRA marker 参数，$\Psi(\kappa)$ 是当前 key 对应的子集。这个机制带来两个工程优点：第一，key 切换不需要更新权重，只需要改变路由 mask；第二，routing mask 在整个 denoising trajectory 中保持固定，因此同一个 key 在采样过程中产生一致的扰动模式。

这一点和 AquaLoRA 也不同。AquaLoRA 是把水印嵌进 LoRA module 或用于 customized Stable Diffusion 的 white-box protection；MOLM 更强调 mixture/routing：同一组已训练 LoRA markers 支持大量 key，不需要每个 key 独立训练。

### 3.4 Watermark extractor：从图像恢复 M-bit key

提取器 $V_{\eta}$ 是一个深度网络，输入图像 $x$，输出 $M$ 个 logits：

$$u=V_{\eta}(x),\quad u=[u_1,\ldots,u_M].$$

logits 经 sigmoid 得到连续 key 估计：

$$\hat{\kappa}=\sigma(u).$$

二进制 key $\tilde{\kappa}$ 可通过四舍五入得到。检测时不一定需要全部 bits 正确，而是计算和目标 key 的 matching bits；归因时则和 key database 中所有注册 key 比较，选择 matching bits 最大且超过阈值的用户。

### 3.5 训练目标：图像不可感知 + key 可恢复

MOLM 只训练 LoRA marker 参数 $\Psi$ 和 extractor 参数 $\eta$，冻结生成器 backbone $\Phi$。训练对每个 prompt $t_n$ 和 latent $q$ 生成 clean image $x_n=G_{\Phi}(q,t_n)$，再采样 key $\kappa$，用 routed LoRA generator 生成 watermarked image $\tilde{x}_n=G_{\Phi+\Psi(\kappa)}(q,t_n)$。

不可感知 loss 用 feature-based reconstruction，例如 LPIPS：

$$L_{\mathrm{imp}}=\mathbb{E}_{\kappa\sim K}\frac{1}{N}\sum_{n=1}^{N}\sum_{k=1}^{K}w_k\Vert\phi_k(G_{\Phi+\Psi(\kappa)}(q,t_n))-\phi_k(G_{\Phi}(q,t_n))\Vert_2^2.$$

这里 $\phi_k$ 是固定感知特征提取器，$w_k$ 是不同层特征权重。它约束水印图像尽量接近同 prompt、同 latent 的原始生成结果。

可验证 loss 是 binary cross-entropy。训练时对水印图像施加随机图像增强 $T\sim\Pi$，再送入 extractor：

$$L_{\mathrm{ver}}=\mathbb{E}_{T\sim\Pi}\frac{1}{N}\sum_{n=1}^{N}\frac{1}{M}\sum_{m=1}^{M}[-\kappa_m\log\sigma(u_m)-(1-\kappa_m)\log(1-\sigma(u_m))].$$

这里 $u=V_{\eta}(T(\tilde{x}_n))$。增强 $\Pi$ 是鲁棒性来源之一：extractor 在训练时就要从 crop、rotation、compression 等变换后的图像中恢复 key。

总目标为：

$$\min_{\Psi,\eta}[L_{\mathrm{ver}}+\lambda L_{\mathrm{imp}}].$$

附录 B.1 给出主要训练配置：LoRA adapters 和 key extractor 训练 12K steps，AdamW，learning rate $1\times10^{-4}$，batch size 4，weight decay 0.01；$L_{\mathrm{imp}}$ 是 VGG backbone LPIPS，$\lambda=1.0$。

### 3.6 检测与归因判决

bit recovery 用 bit accuracy 衡量：

$$\mathrm{BitAcc}=\frac{s(\kappa,\tilde{\kappa})}{M},\quad s(\kappa,\tilde{\kappa})=\sum_{j=1}^{M}1[\kappa_j=\tilde{\kappa}_j].$$

检测任务中，若 matching bits 超过阈值 $\tau$，则判为有效水印。无水印假设下，matching bits 服从二项分布：

$$s\sim\mathrm{Binomial}(M,0.5).$$

论文按目标 FPR 设阈值。默认 $M=28$ 时，TPR@1%FPR 对应 $\tau=20$。归因任务中，数据库有多个用户 key $\kappa^{(i)}$，系统计算每个 key 的 matching score：

$$s_i=\sum_{j=1}^{M}1[\hat{\kappa}_j=\kappa^{(i)}_j].$$

若 $\max_i s_i\ge\tau$，图像归因到 $\hat{i}=\arg\max_i s_i$；否则拒绝为非水印图像。归因实验为了把全局 FPR 控制到 $10^{-3}$，使用更严格的 $\tau=27$。

### 3.9 复现风险与信息缺口

复现风险主要来自工程细节。第一，论文没有在正文中完整列出 extractor 架构，需要参考代码实现。第二，随机增强 $\Pi$ 的完整分布、severity 和训练时采样概率需要从代码或附录细节确认。第三，LoRA adapter rank 的默认值、插入到每个 ResNet block 内部哪一层卷积、scaling factor $\alpha$ 的具体值，正文没有全部展开。第四，FLUX 和 SD v3.5 的适配细节、显存需求、精度设置和训练稳定性需要代码验证。第五，归因实验涉及 1000 users、10 images/user 和 20,000 non-watermarked images，key 数据库构造和阈值选择要严格对齐，否则 FPR/TAR 会偏。

## 4. 与其他方法对比

MOLM 和已有方法的本质差异在于“key 如何控制水印”。Stable Signature、SleeperMark 等方法往往把水印绑定到 decoder fine-tuning 或 trigger training；Tree-Ring、Gaussian Shading 把水印放到初始 latent 或采样过程；WOUAF 用 watermark message 调制 decoder weights；AquaLoRA 用 LoRA 保护 customized diffusion model。MOLM 把 key 变成 routing path：一组共享训练好的 LoRA markers 能支持大量 keys，换 key 只是换激活路径，不需要重新训练。

| 方法类别 | 代表方法 | 核心思想 | 优点 | 缺点 | MOLM 的改进点 |
|---|---|---|---|---|---|
| latent/sampling 水印 | Tree-Ring、Gaussian Shading | 修改初始 latent 或采样轨迹 | 无需训练或检测直接 | 可能需要 inversion，几何攻击弱 | MOLM 直接从图像恢复 key，不依赖完整 inversion |
| decoder fine-tuning | Stable Signature | 微调 decoder 并训练 extractor | 多 bit signature 清晰 | per-key 更新成本高，部分失真弱 | MOLM 不需要 per-key retraining |
| LoRA 水印 | AquaLoRA | LoRA 中嵌入水印 | 参数高效，适合定制模型 | 需要预训练/特定保护场景 | MOLM 用 mixture routing 扩展 key 空间 |
| 权重调制 | WOUAF | 用消息调制 decoder weights | bit recovery 较强 | 训练成本更高，平均攻击有风险 | MOLM 训练约 1 天，无 per-key cost，平均攻击更稳 |
| post-hoc 任意图像水印 | TrustMark、VINE-R | 生成后对图像嵌入水印 | 可用于任意图像 | 几何攻击下弱，非生成过程内生 | MOLM 是 in-generation watermark，与模型来源绑定 |
| MOLM | 本文 | key 路由 LoRA markers | 可换 key、低推理开销、检测与归因兼具 | 依赖模型内插 adapter，不适用于任意已有图像 | 本文方法 |

适用场景是文本到图像服务、模型 API、用户级生成图像归因、模型版本追踪。它不适合没有模型控制权的后处理场景，也不适合只拿到历史图像后再补水印的场景。

## 5. 实验表现与优势

### 5.1 常规检测与失真鲁棒性

Table 1 比较了 bit-recovery methods、detection-only methods 和 post-hoc methods。MOLM 在 SD + MS-COCO 上 FID 27.7，相对无水印反而为 -1.4，SSIM 0.77，PSNR 23.5；bit accuracy 在 undistorted、crop、rotation、resize、brightness、JPEG 下分别为 0.98、0.91、0.84、0.90、0.95、0.89。论文强调 undistorted bit accuracy 超过 0.98，并在各种失真下保持可恢复。

对比上，Stable Signature 在 rotation 只有 0.56、resize 0.72；AquaLoRA 在 rotation 只有 0.45；WOUAF 在部分失真中很强，但训练成本更高。Detection-only 视角下，MOLM 在 SD + MS-COCO 上 TPR@1%FPR 在多数失真下达到 0.96-1.00，同时仍能恢复显式 key，而不是只做二分类。

FLUX 上，MOLM 在 MS-COCO 下 FID 25.8、SSIM 0.95、PSNR 32.3，undistorted/crop/rotation/resize/brightness/JPEG 分别为 0.93、0.89、0.76、0.82、0.92、0.77。SD3.5 上也报告了 28-bit MOLM：FID 26.2，SSIM 0.97，PSNR 36.9，说明方法不只绑定 SD v1.5。

### 5.2 归因实验

归因实验模拟 1000 个注册用户，每个用户 10 张水印图像，共 10,000 in-database images；另外用 20,000 张 non-watermarked images 测 false positive。阈值 $\tau=27$，即最多允许 1 bit error，目标全局 FPR 为 $10^{-3}$。

结果显示，非失真图像下 false positive rate 为 0.02%，true accept rate 为 98.92%，conditional attribution accuracy 为 100%。这说明错误主要来自拒绝而不是错归因。Table 2 进一步显示 JPEG q=80、crop 5%、resize 0.7×、rotation 25°、brightness ×1.5 等常见变换下，accepted images 的 conditional attribution accuracy 仍接近 100%。严重 resize 0.3× 和 90° rotation 会大量被拒绝，而不是被错归因。

### 5.3 图像质量

Figure 3 给出 SD 和 MOLM 的视觉对比。论文结论是 MS-COCO 和 LAION Aesthetics 上，MOLM 输出与原始 Stable Diffusion 结果视觉上难以区分。量化上，FID 相对 vanilla model 的变化小于等于 1.5，SSIM/PSNR 没有系统性下降。这支持“routing-based LoRA marker 不显著破坏图像质量”的 claim。

### 5.4 压缩与 diffusion regeneration attack

Table 3 测 learned compression 和 diffusion regeneration。无 augmentation 训练时，BMSHJ2018 在强压缩 q=1 下 bit accuracy 降到 0.50，Cheng2020 q=1 为 0.70，diffusion regeneration 30/60/100 steps 为 0.72/0.69/0.62。加入 augmentation training 后，BMSHJ2018 q=1/4/8 提升到 0.61/0.95/0.99，Cheng2020 q=1/3/6 为 0.94/0.95/0.97，diffusion regeneration 为 0.85/0.85/0.82。说明训练增强对强压缩和再生成非常关键，但最强 diffusion regeneration 仍不是满分。

### 5.5 Averaging attack

论文按 Yang et al. 的 averaging attack 设定，生成 $k\in\{5,10,20,50,100,200,500,1000,2000,5000\}$ 张图像做平均，测试 removal 和 forgery，并考虑 same-message 与 heterogeneous-message。结果显示，伪造攻击中 MOLM 保持 chance level 约 0.5，即平均图像不能稳定诱导目标水印；移除攻击中，即使平均到 5000 张图像，MOLM 仍保持 bit accuracy 大于等于 0.96。对比 WOUAF，附录 Figure 4 显示 WOUAF removal 会降到约 0.85-0.90。

### 5.6 针对 extractor 的 white-box PGD attack

论文考虑更强自适应攻击：攻击者知道 extractor 和阈值，直接优化输入图像使 $V_{\eta}$ 输出接近随机，同时受 MSE/PSNR 约束。攻击目标为：

$$L_{\mathrm{rem}}(x_{\mathrm{adv}})=\frac{1}{M}\sum_{i=1}^{M}(p_i(x_{\mathrm{adv}})-0.5)^2.$$

约束为：

$$\mathrm{MSE}(x_{\mathrm{adv}},\tilde{x})\le\epsilon,\quad \mathrm{MSE}(x_{\mathrm{adv}},\tilde{x})=\frac{1}{N}\Vert x_{\mathrm{adv}}-\tilde{x}\Vert_2^2.$$

Table 3 显示无 augmentation 时，PGD 随 $\epsilon$ 增大可把 bit accuracy 从 0.93 降到 0.60；有 augmentation 后，在 $\epsilon=10^{-3},10^{-2},10^{-1}$ 下仍为 1.00/0.99/0.96。论文指出更宽松的约束会产生可见失真，说明成功移除需要明显视觉代价。

### 5.7 消融实验

容量消融表明默认 VAE decoder 14 blocks、4 paths/layer 生成 28-bit key 是质量和容量的折中。若在 U-Net 中加入 108-bit routing，FID 增加 4.15，并出现内容和细节变化，说明水印干预位置很重要。Table 5 中，independent bits per convolution 可达 56 bits，bit accuracy 0.89，TPR@1%FPR 0.99，FID 27.9；including attention blocks 为 30 bits，bit accuracy 0.92，FID 28.2；8 paths/layer 为 42 bits，bit accuracy 0.90，FID 27.3。

mapping effect 消融通过随机化每个 active adapter 的权重，看哪些 key bits 翻转。结果显示 key 不是一层一 bit 的简单对应，而是跨层冗余编码；这解释了为什么单个 adapter 被扰动不一定抹除某一位。

sampling configuration 消融显示不同 sampler、steps、CFG 下 bit accuracy 基本在 0.94-0.96，FID 在 25.8-28.5 之间，说明检测不依赖固定采样器。LoRA rank 消融显示 rank 过低如 8 无法可靠解码，较高 rank 提高 bit recovery，但会增加参数和可能的 FID 成本。

### 5.8 证据边界

论文实验覆盖面较广，包括常规失真、learned compression、diffusion regeneration、averaging、white-box extractor PGD、full-knowledge independent retraining、跨数据集和跨模型。但仍有未覆盖点：没有系统评估大幅语义编辑、局部 inpainting/outpainting、图像转视频/截图再压缩、多轮社交平台转码、或攻击者直接拿到 LoRA markers 与 extractor 参数后的强白盒联合作战。

## 6. 学习与应用

论文开源：`https://github.com/Samar-Fares/MOLM-Watermark`。复现时建议先跑 SD v1.5 + MS-COCO 的默认 28-bit 设置，不要一开始尝试 U-Net 108-bit 容量，因为质量退化更明显。

实现要点：

- 冻结 diffusion backbone，只训练 LoRA marker 和 extractor。
- 先选 VAE decoder ResNet blocks 做 routing layers。
- 将 key 切成每层 2 bits，映射到 4 个 adapter path。
- 使用同 prompt、同 latent 的 clean/watermarked pair 计算 LPIPS。
- extractor 训练必须加入图像增强，否则 compression、diffusion regeneration 和 PGD robustness 会明显下降。
- 检测阈值应按 key length 和目标 FPR 由 binomial null hypothesis 推出，不要随意用 0.5 bit accuracy。

方法可迁移到其他生成模型，只要模型有可插入 adapter 的模块化结构。对视频扩散模型、多模态生成模型或语音生成模型也有启发：key 不一定嵌入输出信号本身，也可以控制生成网络内部的轻量可路由参数。但迁移时必须重新验证载体位置，否则可能像 U-Net 108-bit 设置一样牺牲质量。

## 7. 总结

一句话概括：用 LoRA 路由编码水印。

## 9. 复现难度与适合人群

复现难度：中高。

如果只复现默认 SD v1.5 + 28-bit MOLM，难度中等，主要是 diffusion + LoRA + extractor 训练工程；如果要完整复现 FLUX、SD3.5、全部攻击、归因和视觉附录，难度较高。

主要依赖包括 Stable Diffusion/FLUX 权重、LoRA 注入实现、MS-COCO/LAION captions、LPIPS、extractor 网络、图像增强管线、learned compression 模型、diffusion regeneration attacker、PGD attack、FID/SSIM/PSNR 评估和 A100 级 GPU。

最小可复现版本：

1. 在 SD v1.5 VAE decoder 14 个 ResNet blocks 插入 4-path LoRA。
2. 用 10k MS-COCO prompt 训练 12K steps。
3. 先只评估 undistorted bit accuracy、FID、SSIM、PSNR。
4. 再加 crop/rotation/resize/JPEG。
5. 最后补 compression、diffusion regeneration、averaging 和 PGD。

适合读者：生成式水印研究者、模型归因/溯源研究者、LoRA/adapter 方法研究者、生成式 AI 平台安全工程团队。对只做语音水印的人也有方法启发，因为它把“水印容量”转化成“可路由参数路径容量”。

## 10. 简短全面总结

MOLM 面向文本到图像生成模型的水印检测与归因问题，核心目标是在不破坏图像质量、不为每个 key 重新训练的前提下，嵌入可恢复、可归因、抗失真的高熵水印。论文把水印编码统一表述为冻结生成器上的密钥依赖参数扰动，并用 Mixture of LoRA Markers 实现：在 VAE decoder 的多个 ResNet blocks 中放置多条 LoRA adapter path，二进制 key 被切分后决定每层激活哪条 path，整条 routing path 即水印载体。训练只更新 LoRA markers 和 extractor，用 LPIPS 保持同 prompt/latent 下水印图像接近原图，用 BCE 和增强训练保证 key 可恢复。实验在 Stable Diffusion、FLUX、MS-COCO、LAION-Aesthetics 上验证了常规失真、压缩、扩散再生成、平均攻击、extractor PGD 和归因能力。主要贡献是把 LoRA routing 用作可扩展水印载体；关键局限是强白盒参数泄露、复杂语义编辑和更大规模真实平台传播仍需进一步验证。

## 11. 论文写作逻辑分析

### 11.1 Intro 的问题铺垫

论文开头先建立生成图像真实性和来源归因需求，再用四个水印要求组织问题：imperceptibility、fidelity、robustness、detection/attribution。随后把已有方法的失败归纳为鲁棒性、质量冲突和 key 更新成本三个缺口，最后自然引出 LoRA routing。这个铺垫对读者很清晰，因为不是泛泛说“水印重要”，而是直接指向部署瓶颈。

### 11.2 Insight 与 motivation

核心 insight 是把水印从输出空间转为参数扰动空间，并进一步用 LoRA mixture 路由承载 key。这个 insight 从“per-key retraining expensive”自然推出：如果 key 只控制已训练模块的组合，就能换 key 不换权重。论文的 motivation 没有停留在 LoRA 参数高效，而是抓住了 LoRA 可组合、可路由这一点。

### 11.3 Threat model 的承接作用

Problem Setting 明确四类参与方和 removal/forgery attacks，后续实验也按这些攻击展开。检测和归因阈值用假设检验连接到 FPR，而不是只报告 bit accuracy，这让 threat model 和评估指标之间更严密。

### 11.4 方法叙事

方法叙事顺序合理：先给通用框架，再介绍 MOLM routing，再讲 extractor 和 joint training，最后讲 deployment。每个模块都对应一个目标：routing 解决 key scalability，LPIPS 解决 imperceptibility，BCE + augmentation 解决 verifiability/robustness，thresholding 解决 detection/attribution。

### 11.5 实验呼应

实验结构基本沿着 claim 展开：Table 1 证明 detection/robustness，Table 2 证明 attribution，Figure 3 证明 quality，Table 3 证明强攻击鲁棒性，Table 4 证明 efficiency，Table 5/7 证明 capacity 和采样/rank 消融。这个组织方式适合借鉴到其他 watermark 论文。

### 11.6 证据链完整性

最强证据是 averaging attack 和 white-box extractor PGD，因为它们直接回应 intro 中的 adaptive removal 风险。较弱证据是 full-knowledge attack：独立重训后 extractor 输出随机，说明不能伪造同一训练 run 的 routing signature，但它没有等价于“参数泄露下不可移除”。此外，post-hoc methods 比较中，TrustMark/VINE-R 与 in-generation MOLM 的任务边界不同，解释时需要注意。

### 11.7 可借鉴写法

这篇论文的可借鉴点是把系统需求抽象成统一数学框架，再把具体工程设计作为该框架的一个实例。对于自己的论文写作，可以学习它的“general framework -> routing instantiation -> detection/attribution metrics -> robustness suite -> ablation of capacity/efficiency”的结构，这比只描述一个网络模块更容易突出方法的可扩展性和部署价值。
